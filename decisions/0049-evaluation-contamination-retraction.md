# ADR 0049: 評価汚染の撤回 — rule_derived 層の封印スコアは能力指標として無効

- 状態: 採用（撤回告知）
- 日付: 2026-06-26
- 関連: ADR 0043-0048（撤回対象の実装）/ 旧 0.828 撤回（別種の汚染＝過適合）

## 何が起きたか（実質的なリーク）

planA-supreme2 / planA-baseline の **rule_derived 層**（risk_tier / t1_state / t2_mode / t2_role /
t2_relation / quality_regime）の封印スコアは **汚染**しており、**能力（capability）の指標としては無効**。
本 ADR でこれを撤回する。

**原因**: 予測器が GT 生成器 `scenario-corpus/.../gt_derive.py` の規則関数 `f` を**ソースで読んで
逐語実装**した（supreme: `_risk_tier_strict`/`_mode_seq_strict`/`_role_salient` ＝ ADR 0045-0048。
baseline: `_role_geo`/`_mode_geo`/`_scene_from_qos_hist`/`_t3_geo` ＝ ADR-030〜034）。
コーパスの rule_derived GT は `label = f(観測)` という決定的関数で生成されるため、`f` を実装した
予測器は **循環的に ~1.0 で一致**する。これは「答えキーを作る関数を見て写した」＝実質的な**リーク**。

train=eval=seal が一致し、アブレーションで「信号を読んでいる」ことは確認したが、それは
「**過適合（暗記）ではない**」を示すだけで、「**循環（仕様適合）でない**」ことは示さない。両者は別問題。

## 撤回するもの（能力主張として無効）

- supreme 8層平均 **0.9424** / baseline **0.9222**
- 観測5層が 1.0（risk/t1/mode/role/quality）
- 系譜 0.6305 → … → 0.9424（この上昇は「実装が写し `f` に近づいた距離」にすぎない）
- 「**supreme > baseline**」（0.9424 > 0.9222）
- 「**v1.5 は新情報ゼロ**」のスコア論証（両系とも写し `f` で測ったため比較自体が汚染。
  「v1.5 フィールドが v1.4 の決定的関数」というコード上の構造的事実は別途成立するが、
  スコアでの実証は撤回）

## 汚染を除いた正直な評価（独立ラベラ・blind-corpus）

`N04-scenario-contract` ブランチ `experiment/blind-labeler-f` で、**規則を一切見ていない独立エージェント**が
観測だけから自前 labeler `f_blind`（別 f′）を作り、**別の独立生成器**の新世界に supreme をかけて測定:

| 層 | seal 独立一致 | 新分布(fresh) 独立一致 |
|---|---:|---:|
| risk_tier | 0.953 | **0.911** |
| t2_role | 1.000 | 0.728 |
| t1_state | 0.819 | 0.605 |
| t2_relation | 0.770 | 0.616 |
| t2_mode | 0.387 | 0.447 |
| 平均 | 0.786 | **0.661** |

- **頑健に客観的なのは risk(TTC) のみ（独立一致 ~0.91）**。
- role は seal で 1.0 でも新分布で 0.73（salient 選択という規約が複雑場面で分岐）。mode は ~0.45（カスケード
  優先順位が観測から未決定＝規約）。
- 封印の見かけ ~0.99 は **循環 × 分布の優しさ**で二重に盛られていた。

## 結論・規律

- **rule_derived 層の封印スコアは「仕様適合（契約の正しい実装）」の回帰テストであって、能力指標ではない。**
  以後、能力を主張する文脈で使わない。
- **能力の非循環指標**は (1) intent 層（t3/scene。GT が `f` の決定的関数でない）と (2) 独立ラベル評価
  （blind-corpus）に限る。観測は依然合成のため、実世界妥当性はさらに別問題（独立ラベラでも直らない）。
- **コードは保持**する（契約を正しく実装した spec-conformance 実装であり、それ自体は正当な成果）。撤回するのは
  **評価の解釈・スコアの能力主張**のみ。
- 教訓: 予測器を作る側は GT 生成器 `f` を見てはならない（隠れ関数にすべき）。本件は `f` をソースで読んだ
  時点で能力評価としては成立しない。
