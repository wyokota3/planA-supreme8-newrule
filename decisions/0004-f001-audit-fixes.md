# ADR 0004: F-001 監査指摘への対処 — リネージ検算・再登録拒否・非空強制・set_split 削除

- 日付: 2026-06-12
- ステータス: 採用
- 関連: `reports/audit-20260612-1629-F-001.md`(監査レポート)、`specs/GT_SCHEMA.md`(改版)、ADR 0003

## 背景

F-001 の監査(auditor・2026-06-12)で4件の指摘が出た。いずれも「F-001 単体では発火しないが、
F-002(封印)が `meta` を直接信頼した瞬間に封印リーク経路になる」種類のもの。ユーザー判断を仰ぎ、
以下を決定した。

## 決定(ユーザー承認済み)

1. **リネージ検算を拒否表に追加(今回修正)**:
   - root 宣言は3条件(`parents`=[] ∧ `parent_lineage_id`=自身 ∧ `generation`=0)をすべて満たすこと。
   - 非 root の `parent_lineage_id`・`generation` は `parents` 連鎖からの解決値と検算一致しなければ拒否。
   - 監査指摘の「`parents`=[] かつ `parent_lineage_id`≠自身 が通る抜け道」はこれで閉じる。
2. **scenario_id の再登録は拒否**: 無言上書き(リネージの事後改変)を `ValidationError` に変更。
   リネージ不変性を最も単純に担保する。(却下: 版管理 — スコープ増。必要になれば改版。)
3. **文字列必須フィールドの非空を強制**: 契約(GT_SCHEMA「非空のみ要求」)を正とし、実装の「型のみ検査」を
   是正。空文字列は拒否。(却下: 契約を型のみに緩和 — 契約が実装に引きずられる前例を作らない。)
4. **`set_split` を削除**: SPEC に無い手動割当API(ADR 0003 で手動指定案は却下済み)を排除。
   正規の割当経路は `assign_split` のみ。テストの違反状態構成は「`register` が `meta.split` を
   そのまま受理する」データ駆動方式に置き換える(取込・状態復元にも必要な経路)。`payout` の
   防御的非交差検証は維持する。

付随して、複数親(マージ系統)が現仕様で不許容(`LineageError`)であることを GT_SCHEMA に明文化した
(implementer の自己申告事項の明文化。F-003 で必要になれば改版)。

## 影響

- `specs/GT_SCHEMA.md` 改版(拒否表4項目追加・リネージ規則の検算明記・split 経路の明記)。
- テスト改修(test-writer): set_split 依存の書き換え+新規拒否系テスト追加。
- 実装修正(implementer): set_split 削除・検算・再登録拒否・非空チェック追加。
- 差分再監査(auditor)で指摘解消を確認後、F-001 完了(WORKFLOW ステップ8)へ。
