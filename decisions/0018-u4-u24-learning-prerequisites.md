# ADR 0018: U4(T3 状態・リセット源)+ U24(ガードレール① の計数定義・k)の確定

- 日付: 2026-06-13
- ステータス: 採用
- 関連: SPEC `U4`/`U24`/`F-009`/`F-010`/`F-014`、ADR 0006(リセット命令=契約外内部IF)、
  ADR 0013(scene/T3=少量学習)、ADR 0007(guard fail-closed・k 未供給は不合格)、ADR 0002(δ_strong)、
  baseline `external-data/planA-baseline/src/ns_epi/{t3.py,scene.py,hgf.py}`、`specs/GUARD_IF.md`(check_param_budget)
- 決定者: ユーザー承認済み(2026-06-13・4問)

## 背景

U4・U24 は学習モジュール F-009(T3)/F-010(scene)の前提ブロッカー。調査で判明:
- **PSO 入力契約に `episode_id`/`episode_status` は存在しない**(SPEC/ADR の前提語は誤り)。episode_id は
  baseline の ctrl 内部生成物で、**supreme は T3 リセット源を契約から読めず内部 IF で定義必須**(ADR 0006 と整合)。
- baseline T3 は episode_id を受け取るが使わず、固定6tick窓+**無限累積 posterior_buffer**(F-005 no-go と整合)。
- HGF カーネルの**純学習パラメータは6個固定**(κ1,κ2,ω1,ω2,ω3,obs_noise)。belief 6スカラは状態(別)。
  ルール閾値定数は scene ~20 / T3 ~25 個(学習パラメータより桁多い)。データ数=練習用~200(U2 部分確定)。

## 決定: U4(T3 状態の具体形・リセット源)

1. **リセット源 = 注入(入力)**。F-009 = T3 状態機構が **reset 信号を入力として受ける**(改良/強い項目モジュールと
   同じ「ルール/状態層は入力を受ける」流儀)。発火源(scene の cut/regime 変化、または ts ギャップ)は**上流共有基盤**で
   別決定(F-010 or 共有のエピソード境界検出器)。F-009 は注入された境界信号で動く=テスト可能性◎・T3 は源に非依存。
2. **状態形 = 有界窓+集約**。エピソード単位の**有界状態**(固定長窓 + 集約統計)を持ち、**境界(注入 reset)で初期化**。
   無限累積なし(baseline の posterior_buffer 無限問題を解消・SPEC U4「無限累積禁止」を満たす)。
3. **跨ぐ単位 = エピソード**。エピソード時間スケールで統合(baseline のフレーム固定窓の欠点=F-005 no-go を是正)。
4. **リセット点** = 注入 reset 信号の受信時。**粒度** = 有界窓+エピソード集約統計(学習 belief 化は将来の選択肢として残すが、本決定は有界窓+集約)。
   - 注記: 入力契約にエピソードフィールドが無いため reset は内部 IF(ADR 0006)。F-009 はその信号を**入力**として受ける。

## 決定: U24(ガードレール① の計数定義・係数 k)

5. **パラメータ数の定義 = (a) 学習可能パラメータのみ**。過学習の懸念は**学習で更新される連続値**が対象。
   固定ルール閾値定数は数えない(ルール改良の一部=学習でない。F-007/008/011 が「学習しない」のと整合)。
   HGF 系なら各モジュール ~6-10 個。学習が rule 閾値を tune する設計にした場合、その tune 対象は学習可能パラメータに計上する。
6. **係数 k = 0.5**。`param総数 < データ数 × 0.5`(データ数=練習用シナリオ件数 ~200 → **param < ~100**)。
   定義(a)で scene/T3 各 ~6-10 個なら十分余裕。**暫定値**(δ_strong 同様)であり、封印件数(U2)・統計的扱い(U11)
   確定時に見直す。
   - F-014-1 `check_param_budget(param_count, data_count, k)` は既に k を引数で受ける実装(F-014 完了済み)。
     本決定は**供給する値 k=0.5・data=練習用シナリオ件数・param=学習可能パラメータのみ**を確定するもの(F-014 コード変更不要)。

## 影響

- **U4/U24 解除**。F-009(T3)/F-010(scene)が着手可能に。
- **F-009(T3)**: 入力系列 + **注入 reset 信号** → エピソード単位の有界窓+集約状態 → T3 出力。学習可能パラメータ ≤ data×0.5。
- **F-010(scene)**: 変化の持続性・速度の推定(EMA/HGF風)学習。学習可能パラメータ ≤ data×0.5。注: baseline scene は
  HGF カーネル不使用(EMA ベース)と判明。supreme も EMA ベースで可(「HGF系」は EMA 風の意。実装時に確定)。
- **F-014-1**: k=0.5・data=練習用シナリオ件数・param=学習可能パラメータのみ を供給して検査(コード変更不要)。
- **reset 信号の発火源**(scene cut/regime か ts ギャップか)は上流共有基盤の設計で確定(F-010 or 共有エピソード境界検出)。

## 残件・申し送り

- **reset 信号の具体的発火源**は上流基盤(F-010/共有)で確定。F-009 は注入信号で動く(源に非依存)。
- **k=0.5 は暫定**。U2(件数)・U11(統計)確定時に見直し(δ_strong と同じ性質)。
- 学習可能パラメータの厳密な数え方(tune 対象 rule 閾値の扱い)は F-009/F-010 実装時に各モジュールで明確化。
- baseline scene が HGF カーネル不使用(EMA)と判明 → F-010 の「HGF系」は EMA 風の意味で扱う(実装時に HGF カーネル採否を確定)。
- 入力契約に episode フィールドが無い事実は SPEC/ADR の「episode_id/episode_status」前提語の訂正点(出力契約 or 将来語の想定だった)。
