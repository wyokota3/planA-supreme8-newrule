# ADR 0011: F-003 着手方針 — 機構のみ実装・F-003 側でのリネージ突合

- 日付: 2026-06-13
- ステータス: 採用
- 関連: SPEC `F-003` 節 / `decisions/0009-f002-sealset-policies.md`(機構のみ実装の先例)/ `decisions/0010-f002-audit-fixes.md` 決定4(着手条件)/ `reports/audit-20260612-2238-F-002.md`(G1・D1)
- 決定者: ユーザー承認済み(2026-06-13・F-003 step1 の2問)

## 背景

F-003(練習用データ増強)着手にあたり、step1 の仕様確認で2つの未決事項が判明した:
1. 受け入れ条件 F-003-2 が依存する **U17(増強GTの「別系統で確定」の具体ワークフロー)が未解決**(本来 F-003 実装前に確定すべき項目)。
2. ADR 0010 決定4 の**着手条件**(封印後に train を足す「逆方向交差」G1 と、非 root 封印時の検算素通り D1 の検査統合点を設計に含めること)の設計確定。

## 決定

### 決定1: U17 は「機構のみ実装」(ADR 0009 踏襲)

F-002 が ADR 0009 で「機構のみ・実データ未投入」としたのと同じ方針を F-003 にも適用する。`augment` モジュールの責務:

- **F-003-1(機構)**: 増強(派生)レコードに親系統タグを付与し、F-001(`DataGovernor`)へ **train として登録**する。推移閉包で親へ遡及可能(datagov の `resolve_root` を再利用・独自再発明しない)。
- **F-003-2(機構)**: 増強GTの `gt_origin` が**生成器と別系統**であることを記録・契約化し、**別系統で確定/検算できない派生は破棄またはフラグ**する(SPEC 異常系)。具体的な U17 ワークフロー(誰が・どの基準で確定するか)は**実データ投入時まで保留**。
- 生成器(AI生成器)は**注入可能な抽象(callable)**とし、テストは偽生成器で機構を検証する(本物の生成品質・多様性はテスト対象外)。
- **F-003-3(多様性・U12)はテスト対象外**(過剰約束回避・TEST_STRATEGY どおり)。

### 決定2: 着手条件は「F-003 側で突合」(sealset は改修しない)

逆方向交差(G1)/検算素通り(D1)の検査統合点を **F-003(train 追加の単一窓口)に置く**:

- `augment` の登録経路で「**新規 train root ∩ 封印 root = ∅**」を検査し、交差する増強登録を**拒否**する。F-002 が封印登録時に「封印 root ∩ train root = ∅」を検査するのと**対向**で、両方向を閉じる(G1 の継続検証点が F-003 に出来る)。
- **D1 対策**: 突合に使う root は `augment` 側で **governor の推移閉包(`resolve_root`)により再解決**し、保存済み `parent_lineage_id` を無検算で信頼しない。封印 root 集合は sealset から取得するが、augment は root ID 集合として扱う(封印本体 gt には触れない)。
- `augment` は `DataGovernor`(train 権威)と `SealStore`(封印 root 集合の供給元)を**受領**して突合する。

### 決定3: ADR 0010 決定4 推奨案(datagov 単一権威化)は不採用

「sealset が governor へ封印 meta を登録し datagov を単一リネージ権威にする」案は採らない。理由:

- **F-002(done・監査 done 判定済み)を再改修せず blast radius を最小化**。封印の現設計(governor 非登録=封印 meta を datagov に載せない)を維持する。
- train 追加の単一窓口は F-003 なので、そこに継続検証点を置けば逆方向交差(G1)は閉じる。

## 影響

- 修正ループ: test-writer(F-003 受け入れ条件のテスト)→ implementer(`src/supreme/augment.py` 新規 + `__init__.py` 登録)→ auditor。
- `augment` は `governor` と `SealStore` を受領して突合する新規モジュール。
- 既知の残置(申し送り):
  - **U17 の具体ワークフローは実データ投入時の課題**として残置(ADR 0009 と同じ性質)。
  - **sealset 内部の D1 は本 ADR では未修正**(F-003 の突合は独自 root 再解決で回避する設計)。`sealset.sealed_lineage_set` を F-003 以外が使う場合の D1 は別途(低優先・監査記録済み)。
  - 多様性(U12)・統計的有意性(U11)は対象外。
- U2 は部分確定(練習用は最大200件程度)。量に依存する受け入れ条件は係数表現とし、件数自体はテストの本質にしない。
