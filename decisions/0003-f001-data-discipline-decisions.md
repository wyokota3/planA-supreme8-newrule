# ADR 0003: F-001(データ規律基盤)の設計確定 — データソースのピン留め・GTスキーマ・割当規則

- 日付: 2026-06-12
- ステータス: 採用
- 関連: `specs/SPEC.md`(F-001/U7/外部参照)、`specs/GT_SCHEMA.md`(新規)、WORKFLOW ステップ1(F-001)

## 背景

F-001 のテスト設計に入る前提として、仕様レビュー(2026-06-12)で保留にしていた4点が
F-001 の実装範囲を直接決めるためユーザーに確認し、以下の回答を得た:

1. GT 単一スキーマの実体 → **実データから導出**
2. 練習/封印の分割割当の発生源 → **datagov が自動割当**
3. 親系統IDの付与規則 → **元シナリオは自身が root**
4. F-001-2 の検証タイミング → **フィクスチャで検証(2段階)**

## 決定

### 1. データソースのピン留め

シナリオ+GT 20件の実体は `https://github.com/wyokota3/N04-scenario-contract.git`
@ `de77b0478eb62b94f649197218caad6c4af8bd3a` の `scenarios/v021_core/`(20シナリオ・210フレーム)。
各シナリオは `scenario.yaml` / `pso_input.jsonl`(PSO-Snapshot/1.4) / `ground_truth.yaml` の3点組。
副産物として同リポジトリ `contracts/` に EPI 入出力契約 v1.4 の実体
(`ns_epi_input_contract_v_1.4_pso_snapshot_delta.md`、`ns_epi_output_contract_v_1.4.md`)を確認し、
U7 のピン留めに反映した(中身の精査は F-006 前のまま)。

### 2. GT 単一スキーマ

実データ20件(構造は全件一貫)から `specs/GT_SCHEMA.md` を導出した。
meta(datagov 管理層)/ gt(実データ由来の本体層)/ custom(不透明パススルー)の3層。
突合キーは `(scenario_id, ts)`。拒否/警告の2段バリデーション
(構造・型・親系統不明・確率域外・t2 クラスキー不一致は拒否、分布合計≈1 は警告のみ)。
文字列 enum の値集合は U7 精査まで閉じない。
Anomaly 項目は GT に直接フィールドが無いことを明記し、対応付けは U10 に委ねた。

### 3. 分割割当は datagov の自動割当(決定的)

`assign_split(params)`: 封印件数/比率＋適格フィルタを受け、適格 root 親系統IDの
sha256 安定ソート順に割当。乱数・時刻非依存で同一入力→同一割当。割当は版として記録。
(却下: 研究者の手動指定を基本とする案 — ユーザー判断で自動割当を選択。)

### 4. 親系統IDの付与規則

元シナリオ(人手含む)は自身が root(`generation`=0)。派生は `parent_lineage_id` を親から継承し
推移的に root へ畳む。親不明データは登録拒否。

### 5. F-001-2 の2段階検証

F-001 完了判定は合成フィクスチャ(ダミー封印GT・ダミー baseline 結果GT)との突合で行い、
F-002/F-005 実装時に実GTで再検証する。(却下: F-001 完了判定からの除外 — 検証可能性を優先。)

## 影響

- `specs/GT_SCHEMA.md` 新規作成。`specs/SPEC.md` の F-001 節・U7・外部参照を更新。
- test-writer は GT_SCHEMA.md を契約としてテストを書ける(曖昧さ解消)。
- 制約: スキーマは v021_core の現データに基づく。契約 v1.4 の精査(U7)や封印GTの実態(F-002)で
  差分が出た場合は GT_SCHEMA.md を改版し、差分を ADR で記録する。
