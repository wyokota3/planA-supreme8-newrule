# ADR 0020: F-009 T3 改良 — エピソード集約+局所ロジスティック少量学習(計測根拠)

- 日付: 2026-06-14
- ステータス: 採用
- 関連: ADR 0013(T3=少量学習)、ADR 0018(U4/U24: リセット源=注入・有界窓+集約・学習可能paramのみ・k=0.5)、

  `reports/erroran-20260612-F005.md`(T3 分散型誤り)、baseline `external-data/planA-baseline/src/ns_epi/t3.py`、T3 再走計測

## 背景

F-009(T3 時系列統合)step1。前提(U4/U24)は ADR 0018 で確定済み。baseline T3 を全210フレーム再走
(格納値と**100%一致**=計測の健全性確認済み・acc 0.5857)して根本原因と学習設計を根拠化した。

## 計測結果(F-005「瞬間証拠に飛びつく」を構造で特定)

- baseline T3 の `volatility = max(0.12, flip_rate)` の flip_rate は**その tick の1ステップ変化フラグのみ**。
  **エピソードに渡る不安定さの累積状態が存在しない**。posterior_buffer は**無限累積だが分類に寄与しない**(stability のみ)。
- conv 判定(`windowed conv>0.3`)は**単一スパイク1個**で6平均が超えうる(持続を要求しない)→ conv 飛びつき。
- traffic 判定(`volatility>0.2`)は**その tick**で要求 → flip=0 の tick はゲート落ち、累積不安定を見ない → traffic 見逃し。
- 誤分類: **conv 飛びつき14件**(ns007群5=持続conv比率0.00-0.20 瞬間 / ns016群6=0.83-0.91 真に持続)、
  **traffic 見逃し7件**(エピソード切替率 median 0.33・flip累積 0.30 vs quiet TP 0)。
- 反実上界: 持続conv比率 T=0.3 で conv飛びつき5件是正・巻き込み0。traffic は単一閾値では衝突残る
  (switch_rate≥0.2 で7回復だが巻き込み7 / flip_mean≥0.3 で4回復・巻き込み1)→ **学習器の同時最適化が必要**。

## 決定

### 決定1: 有界窓+エピソード集約の状態機構(U4 確定の具体化)

baseline の**無限 posterior_buffer を、固定長窓(≤W)+ エピソード集約統計に置換**する:
- 集約特徴: **持続conv比率**(エピソード先頭〜現在で conv系 argmax だった割合)、**切替率**(mode 変化数/フレーム数)、
  **flip累積**(flip の平均/累積)、**posterior 集約**(平均・分散・**トレンド**)。
- **トレンド等の追加集約特徴で ns016群(持続比率では分離不可な6件)の分離を試みる**(ユーザー決定)。
- 状態は**注入 reset 信号の受信時に初期化**(ADR 0018: リセット源=注入・発火源は上流共有基盤)。これで stability も
  有界窓の分散になり、**F-009-2(reset 後に初期値復帰を検証可能)**を満たす。

### 決定2: 学習器 = 局所ロジスティック(集約特徴に学習可能な重み+バイアス)

- エピソード集約特徴に対し、**誤りの集中する conv/traffic/quiet の影響境界(~3)**を**学習可能な重み+バイアス**で
  同時最適化する**局所ロジスティック**。学習可能 param ~7-21 ≪ 予算100(U24・k=0.5・data~200)。
- T3 10クラスのうち**学習が触るのは conv/traffic/quiet 境界**(誤りの震源)。他クラスは baseline 由来の規則/fallback を
  踏襲(忠実再現の流儀)。これにより「見逃し(traffic)」と「飛びつき(conv)」の衝突を学習で解く。

### 決定3: 状態保持の決定性とリセット(F-009-1/F-009-2)

- **F-009-1(再現性)**: 同一入力系列 + 同一リセット列で出力が完全再現(決定的状態機構・乱数/時刻なし・F-004-2 合格)。
- **F-009-2(リセット初期化)**: 注入 reset 信号後に状態(窓・集約累積)が**初期値へ戻る**ことを検証可能(状態を外から
  取得/注入できる API・F-006 T1 / F-010 の流儀)。
- 学習(fit)は**決定的手順**(乱数なし・grid/座標降下)。同じ練習データで2回 fit すると同一 params。

### 決定4: スコープ = T3 状態機構+分類器(独立実装・上流は共有基盤)

- supreme が T3 状態機構+ロジスティックを**独立実装**(baseline/external/ns_epi を import しない・F-006 独立性の流儀)。
- 入力 = T2 mode 出力系列 + 注入 reset 信号。証拠抽出・T2 は上流の共有基盤(スコープ外)。
- 語彙 v1.4: T3 10クラス(quiet_stable/conv_participating/sustained_alert/env_shift/env_start/crowd_tendency/
  traffic_unstable/hazard_declining/uncertain_context/alert_required)。

## 影響

- F-009 は supreme の T3 モジュール(有界窓+エピソード集約状態機構 + 局所ロジスティック + 注入リセット + 決定的 fit)を実装。
- テストは F-009-1(再現性)・F-009-2(リセット初期化)・エピソード集約特徴の機構・分類器構造・**学習可能 param ≤ data×0.5**・
  fit 決定性 を固定(F-010 の性質契約 + 状態/リセットの具体契約)。
- F-009-3(F-013 で項目別対比が測定・報告)は F-013 で測定(改良は成功目標)。

## 残件・申し送り

- **実際の学習値**(fit 後の重み/閾値)は実装の学習実験で決定。最終 T3 acc 改善は F-013 で測定(成功目標)。
- **ns016群6件**は posterior トレンド等の追加集約特徴で分離を試みるが、なお分離不可なら残差として記録(別の誤差モード・
  GT 語彙ニュアンスの可能性)。
- **reset 信号の発火源**(scene cut / ts ギャップ等)は上流共有基盤で確定(ADR 0018 申し送り)。F-009 は注入信号で動く。
- 窓長 W・集約特徴の最終セットは実装時に確定(予算内)。
