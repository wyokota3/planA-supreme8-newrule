# ADR 0002: 誤差許容の2分割(ε/δ_strong)と封印アクセスの機械的定義(開封トークン)

- 日付: 2026-06-12
- ステータス: 採用
- 関連: `specs/SPEC.md`(U5/U24/F-002/F-004/F-006/F-013/F-014)、`specs/TEST_STRATEGY.md`、仕様レビュー(spec-reviewer・2026-06-12)の質問 Q2/Q5/Q6 への回答

## 背景

2026-06-12 の仕様レビューで、ブロッカー U5「誤差許容幅」に**意味の異なる2つの量**が混載されていることが指摘された:
(a) T3 再現性判定の誤差許容、(b) 強い項目の性能低下の許容幅。さらに「相対誤差X%」は分母ゼロ近傍で破綻する。
また封印アクセスの「1回のみ」「評価フェーズ」が機械的に定義されておらず、ガードレール②(F-014-2)が実装不能だった。
ユーザーは Q2(許容幅は別数値・具体値は委任)と Q6(アクセス定義は委任)を Claude Code に委任した。

## 決定

### 1. U5 を U5a / U5b に分割

- **U5a(再現性判定 ε)**: 分類項目=完全一致。連続値= `|a−b| ≤ ε_abs + ε_rel·max(|a|,|b|)`、**ε_rel=1e-6、ε_abs=1e-9**。
  - 根拠: 学習/評価の環境一致(U23 既定方針)の下では、再走差は浮動小数点演算の誤差オーダー。ε_rel=1e-6 は GPU の縮約順序差(典型 1e-7 前後)を吸収しつつ、T3 の真のドリフト(桁違いに大きい)は隠さない。絶対項 ε_abs=1e-9 により値がゼロ近傍でも判定式が破綻しない(numpy.isclose と同形)。
  - 前提: 環境一致。環境を跨ぐ構成に変える場合は ε を再決定する(その際はドリフトを隠さないことの確認を別途要する)。
- **U5b(強い項目の低下許容幅 δ_strong)**: 項目別・**絶対値 0.02**([0,1] スコア)。
  - 根拠: 封印は少数精鋭(数十件規模を想定)であり、0.02 は概ね「1件の判定反転」相当の分解能。これ未満の差はデータ量的に意味を持たない。
  - **暫定値**: 封印件数(U2)と統計的扱い(U11)の確定時に見直す。テスト戦略の穴7(累積劣化)はこの値でも残る点に注意。

### 2. 封印アクセスの機械的定義(開封トークン方式)

- **開封セッション**: 封印アクセスの計数単位。F-013 の1実行に単一のセッションIDを発行し、supreme 測定と baseline 再計測(入力生成・出力取込)の読込を同一セッション内で行う限り「1回」と数える。
- **開封トークン**: 「評価フェーズ」の機械的定義。guard(F-014)がガードレール事前検査の合格を条件にトークン(セッションID+発行時刻)を発行し、F-013 終了で失効させる。封印セットの読み出しは有効トークン保持時のみ許可、それ以外は拒否+セッションID付きログに記録。
- ガードレール②(F-014-2)の検査対象は「有効トークン期間外のアクセスが0件」かつ「本番封印の生涯開封セッション数が1」となる。

## 代替案と却下理由

- **ε を単一の相対誤差%のまま使う**: 分母ゼロで破綻し、再現性(微小値)と性能維持(スコア差)という別物を1つの数字で縛ることになるため却下。
- **δ_strong を相対値にする**: スコアが [0,1] の有界値であり、項目間で基準値が大きく異なると相対値は直感に反する許容を生むため絶対値とした。
- **「評価フェーズ」を時刻ウィンドウや手動宣言で定義**: 機械検査できず穴8(ログ外アクセス)をさらに広げるため却下。トークンは少なくともアクセスAPI 経由の読み出しを構造的に縛れる。

## 影響

- 変更: `specs/SPEC.md`(U5 解決・U24 採番・F-002/F-004/F-006/F-013/F-014/非機能/用語集)、`specs/TEST_STRATEGY.md`(F-004 のブロック範囲縮小ほか)
- ブロッカーが3件→2件に減少(残: U7 契約実体のピン留め、U10 指標定義)
- F-004 は「指標式の欠落時停止」+「T3 再現判定」のテスト・実装が着手可能になった(採点式そのものは U10 待ち)
- 限界: ε・δ_strong の妥当性自体を検証する上位テストは存在しない(テスト戦略・穴4)。封印保全はログ/トークン経由に限られ、ファイル直読み等は防げない(穴8)。技術ロック(暗号化等)は未設計のまま。
