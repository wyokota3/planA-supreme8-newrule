# ADR 0013: U1(混合比)の確定 — F-005 構造原因に基づく項目別配分

- 日付: 2026-06-13
- ステータス: 採用
- 関連: SPEC `U1`/`U3`/`F-007`〜`F-011` 節、`reports/erroran-20260612-F005.md`(構造原因)、
  baseline 自身の ADR-028/029(scene/T3 のルール限界=no-go 記録・F-005 で参照)
- 決定者: ユーザー承認済み(2026-06-13・2問)

## 背景

U1(混合比: どの項目を学習に回すか)は改良モジュール群 F-007〜011 の関門だった
(各 module は U1/U3 確定まで「枠のみ」)。U1 の確定時期は「F-005 完了後・各改良モジュール
着手前」(SPEC U1)。F-005 のエラー分析(U3 解決済み)が項目別の構造原因を出し、手段を示唆していた。

## 決定

### 項目別の改良手段(配分)

| 項目(機能) | 手段 | 構造原因(F-005)と方針 |
|---|---|---|
| **mode(F-007)** | **ルール改良** | 静穏からの過剰遷移・隣接境界の振動 → 閾値再較正・ヒステリシス導入。時間平滑化を入れる場合 T3(F-009)の責務と干渉させない |
| **relation(F-008)** | **ルール改良** | addressing 発火条件・優先度+欠落クラス → 優先度の再設計+欠落クラス(departing/unrelated)の明示ルール追加。**配線追加ではない**(配線漏れ仮説は F-005 で棄却) |
| **quality(F-011)** | **ルール改良** | 順序尺度の境界が1段悲観側にズレ(較正問題)→ 境界の再較正。改良容易性: 高 |
| **scene(F-010)** | **少量学習** | 変化の持続性・速度を測る仕組みの不在・閾値調整だけでは両立不能 → 変化量推定(HGF系等)。少量学習の最有力 |
| **T3(F-009)** | **少量学習** | エピソード時間スケール統合の不在・分散型誤り → 状態保持+時系列統合 |

### scene/T3 は学習に踏み込む(ルール先行しない)

baseline 自身が ADR-028/029 で scene/T3 を**ルールの限界(no-go)**と記録しており、ルール先行は
二度手間になる可能性が高い。よって F-009(T3)/F-010(scene)は最初から少量学習を実装する。

### 学習・非学習の境界(ガードレール①との関係)

- **学習項目 = scene / T3 のみ**。ガードレール①(param 総数 < 練習用 data 数 × k・F-014)の範囲内で
  学習する。param 数の数え方と k は **U24**(学習項目実装前に確定が必要)。
- **ルール改良項目(mode/relation/quality)は学習しない**(param 予算を消費しない)。
- 強い項目(T0/T1/role・F-006)も流用で学習しない。

## 影響

- **U1 解除**。F-007〜011 が「枠のみ」から**着手可能**に(各 module の手段が確定)。
- 各改良モジュールの SPEC「正常系・異常系・境界条件: 未決定(U1/U3 確定後)」を手段確定で更新。
- 学習項目の実装前提(各 module の着手条件として残る):
  - **F-009(T3)**: U4(T3 状態形・リセット源)+ U24(k)。
  - **F-010(scene)**: U24(k)。
  - 学習FW(U13: Python/PyTorch 暫定)・学習/評価の環境一致(U23)も学習項目で効く。
- **F-008** は配線漏れ仮説をコード化しない(F-005 で棄却・SPEC F-008 注記どおり)。

## 残件・申し送り

- **U24(k: param 予算の係数)**は学習項目(scene/T3)実装前に確定が必要(ガードレール①の根拠)。
- **U4(T3 状態形・リセット源)**は F-009 実装前に確定が必要(既存・SPEC U4)。
- 「baseline 再計測値を上回る」は合否ゲートでなく**成功目標**(2026-06-12 再分類)。各改良の受け入れ条件は
  F-013 の封印評価で項目別対比が測定・報告されること。
- ルール改良の具体閾値・較正値は各 module 実装時(test-writer→implementer)に F-005 の混同行列を根拠に決める。
