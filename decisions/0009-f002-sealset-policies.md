# ADR 0009: F-002(封印テストセット)の実装方針 — 機構のみ・分離保管・ダミーモード内包

- 日付: 2026-06-12
- ステータス: 採用
- 関連: `specs/SPEC.md`(F-002/U2/U17)、`specs/GUARD_IF.md`(トークン契約)、`specs/GT_SCHEMA.md`、ADR 0002/0008

## 背景

F-002 着手時点で、人手の本物シナリオ+人手確認GT は未作成(研究者の作業)。封印件数(U2 残)も未定。
アクセス制御の実装形(SPEC「技術的に遮断」とテスト戦略・穴8 のギャップ)と、合成ダミー封印の
所有者(仕様レビュー保留 Q16)が未決だった。ユーザーに確認し以下を承認された。

## 決定(ユーザー承認済み・2026-06-12)

1. **スコープは機構のみ**: 封印登録・アクセス制御・ログ永続化の機構を実装し合成データで検証。
   実データ(人手シナリオ+人手確認GT)の投入は研究者の作成後に別途実施(機構はそのまま使える)。
   U17(GT 確認ワークフロー)は研究者の運用として未決継続。機構は gt_origin 等の来歴を記録するのみ。
2. **アクセス制御 = 分離保管+トークンゲート+永続ログ**:
   - 封印データは専用ディレクトリ(リポジトリ外を推奨・パスは構成可能)に分離保管。
   - 読み出しは GUARD_IF のトークン検査経由のみ(SealGuard / SearchGate)。
   - 全アクセス試行(拒否含む)を**永続 JSONL ログ**(SealAccessRecord 形式)に追記し、
     生涯1回をプロセス跨ぎで検証可能にする(GUARD_IF 運用規約2 の実装)。
   - 穴8(ログを介さないファイル直読み)は残る既知限界として明記(暗号化は採らない=運用負荷と
     stdlib 制約。却下案として記録)。
3. **合成ダミー封印は F-002 のダミーモード**: 本番と同一機構を `production=False` の SealGuard と
   対応づけて提供し、ドライランE2E・常用テストの経路を確保(穴2 対策。Q16 の解)。
4. **封印件数(U2 残)は未定のまま**: 機構は件数非依存。人手作成の見通しが立った時点で U11 と連動して確定。

## 影響

- F-002 はファイルI/O を伴う初の機能(分離保管・永続ログ)。テストは tmp ディレクトリで実施。
- F-013 の「生涯1回」検証は永続ログ+`audit_seal_access`+`lifetime_session_count` の突合で成立。
- 実データ投入時の手順(登録→非交差検証→封印)は機構の関数をそのまま使う。
