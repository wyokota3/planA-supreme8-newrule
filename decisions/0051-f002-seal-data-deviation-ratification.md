# ADR 0051: F-002 封印データ逸脱の事後批准 — AI 生成コーパスでの封印評価を逸脱として記録する

- 状態: 採用(事後批准・逸脱の記録)
- 日付: 2026-07-02
- 関連: SPEC F-002(封印テストセット構築)/ SPEC 判断6(封印は人手の本物・少数精鋭)/
  ADR 0023(F-013 封印評価設計)/ ADR 0049(評価汚染の撤回)/ ADR 0050(strict ゲート化)
- 契機: 監査 2026-07-02 所見 — 「実際の封印評価は SPEC F-002/判断6 の規定と異なるデータで
  実施されたが、SPEC 改訂も専用 ADR も無く、正当化はレポート内の一文のみだった」。

## 規定(何が約束されていたか)

- **SPEC F-002**: 封印テストセットは「**人手の本物シナリオ＋人確認GT**を少数(精鋭)構築。
  学習・調整に不可触、最終評価で一度だけ開封」と規定。
- **SPEC 判断6**: 選択肢 (a)「全AI生成のみで封印」を検討した上で**却下**し、(b)「人手の本物・
  少数＋baseline 同一封印再計測」を採用。却下理由は明文で「**AI作問にAI採点だと実力でなく
  AI同士の一致を測る循環になる**」「(a)=次善。親単位分割で凌げるが、AI作問にAI採点の
  循環リスクが残る」。

## 実際(何が行われたか)

- 実際の封印評価(`reports/sealeval-coverage_v1-seal-20260623.md` / 同 `20260624-improved.md`)は、
  **AI 生成コーパス** `coverage_v1`(`N04-scenario-contract@main` commit `2f3da56`)の
  **lineage-disjoint 分割**(fit=train 406 シナリオ / 評価=seal 86 シナリオ・408 フレーム)で
  実施された。人手の本物シナリオ・人確認 GT は使われていない。
- 正当化はレポート内の一文(「**train と lineage-disjoint(README 保証)=汚染ゼロ**」)のみで、
  SPEC F-002 の改訂も、判断6 の再検討も、逸脱を記録する専用 ADR も作られなかった。
  SealStore(F-002/F-013 のセレモニー機構)の開封経路も本評価では通っていない
  (harness 直接評価)。

## 帰結(逸脱が何を招いたか)

判断6 が警告した循環リスクは**そのまま顕在化**した(ADR 0049 の評価汚染)。

- lineage-disjoint は「同じ親シナリオの**暗記**」を防ぐが、「GT 生成規則 f
  (`gt_derive.py`)の**写し**」は防げない。rule_derived 層の GT は `label = f(観測)` で
  生成されるため、f を実装した予測器は封印分割に関係なく循環的に ~1.0 で一致する。
- 「汚染ゼロ」の一文は暗記汚染(データ交差)のみを見ており、**生成規則汚染**(判断6 が
  「AI作問AI採点の循環」と呼んだもの)を見落としていた。封印スコア 0.9424 の系譜が
  能力主張として撤回(ADR 0049)されたのは、この見落としの直接の帰結である。

## 決定(事後批准と将来の規律)

1. **事後批准**: 2026-06-23/24 の封印評価は、SPEC F-002/判断6 からの**逸脱であったと認めた上で**、
   「spec-conformance の回帰値・項目別対比の実務的基準」としては遡及的に承認する
   (ADR 0049 の再解釈と一貫: 能力指標としては無効・回帰テストとしては有効)。
   逸脱の隠蔽・上書きはせず、本 ADR を逸脱の一次記録とする。SPEC F-002 の要件本文は
   書き換えない(注記で本 ADR を参照)。
2. **将来の封印の規律**(次回以降の封印評価はいずれかを満たすこと):
   - **隠れ関数化した独立生成器**: GT 生成規則 f を予測器開発者(人間・AI とも)から
     構造的に隠す(別リポジトリ・アクセス遮断・独立エージェント作成の f′ 等。
     ADR 0049 の blind-labeler 実験が先行例)。生成規則をソースで読める状態の
     コーパスは封印データとして不適格。
   - **人手データ**: SPEC F-002 原文どおり人手の本物シナリオ＋人確認 GT。
   - いずれの場合も **SealStore セレモニー経由の1回開封**(`open_eval_session` →
     単一トークン下 read → revoke・F-002-2/F-013)を通すこと。harness 直接評価は
     開発時の diagnose に限る。
3. 封印データの選定・変更は、レポート内の一文でなく**専用 ADR**(本 ADR の書式)で
   事前に記録すること。

## 教訓

「lineage-disjoint =汚染ゼロ」は暗記汚染にしか成立しない等式だった。封印の防御は
(1) データ交差(暗記)と (2) 生成規則の可視性(写し)の**二軸**で設計する必要があり、
判断6 はこの第二軸を最初から警告していた。規定からの逸脱は、たとえ善意の実務判断でも
その場で ADR に残す(本件は 9 日遅れの事後批准になった)。
