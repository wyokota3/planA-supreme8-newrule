# ADR 0021: U8(探索空間・手法・停止)+ U18(試行上限)の確定 — F-012 組み合わせ探索の設計

- 日付: 2026-06-14
- ステータス: 採用
- 関連: SPEC `U8`/`U18`/`F-012`、ADR 0007(ガードレール・SearchGate)、`specs/GUARD_IF.md`(SearchGate.request_continue / check_param_budget / check_trial_cap)、
  ADR 0017(F-006 強い項目)、ADR 0018(U24: param予算)、ADR 0002(δ_strong)、F-007〜011 改良モジュール
- 決定者: ユーザーが U8 をオーケストレーターに委任(2026-06-14・「最適だと思う方法で」)・U18 は U8 に準拠・本決定をユーザー承認

## 背景

F-012(組み合わせ探索)の前提 U8(探索空間・手法・停止条件)・U18(試行上限/撤退基準)を確定する。
supreme 本体(弱い5項目改良 mode/relation/quality/scene/T3 + 強い項目 T0/T1/role)は構築済み。
F-012 の核心は**探索の規律**(封印非アクセス・練習スコアのみ・上限内・決定的)= 方法論検証層。

## 決定: U8

### 探索空間(探索軸)
- **候補 = 5改良モジュールの構成の組み合わせ**。各改良モジュール(mode/relation/quality/scene/T3)について
  **ON/OFF + tunable モジュールの離散ハイパラ候補(各数個)**を軸とする。
- **強い項目(T0/T1/role)は流用で常時 ON**(探索対象外・F-006)。
- 空間は**有界**(モジュール数 × 離散候補数)で、試行上限が意味を持つ。

### 手法 = 決定的 greedy 座標上昇
- 基準構成(全改良 ON・各既定ハイパラ)から開始し、各軸を順に走査して**練習スコアを最も改善する変更**を採用、
  改善が無くなる(収束)か試行上限に達するまで反復。**決定的**(乱数・時刻なし・固定順走査)= 再現的(F-004-2)。

### 目的関数 = 練習データのハーネススコア
- 各候補を **F-004 ハーネスで練習データに対し採点**(注入スコアラ)。**封印セットには一切アクセスしない**(F-012-1)。
  選定は**練習用スコアのみ**(F-012-2)。スコアラ(supreme を練習データで走らせて出力を得る)は**上流共有基盤の注入**
  (end-to-end は証拠抽出基盤待ち。F-012 はスコアラを受領する形で規律をテスト)。

### 制約 = ガードレール(SearchGate/aggregate 経由)
- 各候補は **param 予算(F-014-1・学習可能パラメータ < data×0.5・U24)**と**強い項目の δ_strong 維持(F-006-1)**を
  満たすこと。違反候補は**不採用**(SearchGate.request_continue が aggregate 不合格で False を返す経路)。
- **封印は一切開かない**(開封は F-013 の最後の1回のみ・GUARD_IF)。

## 決定: U18(U8 に準拠)

- **試行上限(ハード上限)= 50**。bounded な module-config 空間の greedy 座標上昇(~5軸×数候補)を十分カバーし、
  **過剰探索=探索による過学習(R7 再来)を防ぐ**ハード ceiling。
- **無改善 patience = 10**(撤退基準): 連続10試行で練習スコアが改善しなければ撤退。
- **暫定値**(δ_strong 同様)。探索空間サイズ・統計(U11)確定時に見直す。
- F-014-4 `check_trial_cap(trial_count, cap)` に **cap=50** を供給(F-012-3 を満たす。F-014 は cap を引数受領済み=コード変更不要)。

## F-012 のスコープ

- F-012 = **探索オーケストレーション**: 候補生成(module-config 軸の greedy)+ **注入された練習スコアラ** + guard(SearchGate)で
  規律を強制し、上限内で練習ベスト構成を選定。
- テストは F-012-1(封印非アクセス)・F-012-2(練習スコアのみ)・F-012-3(試行 ≤ cap=50)・決定性(F-004-2)・
  ガードレール違反候補の不採用 を固定(方法論検証層)。スコアラ・supreme の end-to-end 実行は上流(スコープ外・注入)。

## 影響

- **U8/U18 解除**。F-012 着手可能に(残ブロッカー: F-013 の着手条件のみ)。
- F-012 は guard(SearchGate)・harness(注入スコアラ)を再利用。封印(sealset)は触らない。
- 出力 = 練習ベスト構成(F-013 が封印で最終評価する確定組み合わせ)。

## 残件・申し送り

- **スコアラ(supreme を練習データで走らせる end-to-end)** は上流共有基盤(証拠抽出・各モジュールの結線)待ち。
  F-012 は注入スコアラで規律をテストし、実探索は基盤完成後(F-013 前)。
- **cap=50・patience=10 は暫定**(U2 件数・U11 統計で見直し)。
- 離散ハイパラ候補の具体セットは実装時に確定(各改良モジュールの計測済み既定 ± 数候補・予算内)。
- F-013 の着手条件(SearchGate×SealStore 経路合成・ADR 0010)は F-013 で解く(F-012 は封印を開かないので未抵触)。
