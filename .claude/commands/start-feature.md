引数として渡された機能ID(例: F-001)について、`./WORKFLOW.md` の8ステップに従って実装ループを開始してください。

機能ID: $ARGUMENTS

## まず最初にやること

1. `./specs/SPEC.md` から該当機能の節を読み込む
2. `./specs/TEST_STRATEGY.md` の該当機能に関する記述を読み込む
3. 未決定事項に該当機能が依存する項目があれば、私に確認する
4. 確認が完了したら、ステップ2(テスト設計)に進むことを宣言してから `test-writer` サブエージェントを呼ぶ

## ステップ移行の規約

- 各ステップ完了時にgit commitを打つ(WORKFLOW.md のコミット規約に従う)
- 各ステップで私の承認を待つ(ステップ3、ステップ8は特に厳密に)
- サブエージェントを呼ぶ前に「これから何を依頼するか」を私に伝える
- サブエージェントの結果を、要約と原文セクション両方で私に提示する

## 詰まったとき

- 3回失敗したら自動継続を止めて状況を報告
- 仕様の曖昧さを発見したら勝手に解釈せず質問する
- ステップを飛ばしたい誘惑があっても飛ばさない

開始してください。
