30 秒サマリ

supreme8 は、環境音から状況を読む 8 層 EPI（risk_tier / t1_state / t2_mode / t2_role / t2_relation / t3_hypothesis / quality_regime / scene_regime）を出力する決定的エンジンである。中核は T2（mode / role / relation）を 本来型 NeuPSLで解く点にある——すなわち ①ニューラル述語（生特徴 → 軟真理値の微小 MLP）、 ②Łukasiewicz 緩和の重み付き論理ルール 本、 ③シナリオ内の全フレーム×3 層を同時最適化する結合 MAP 推論（HL-MRF）の 3 要素を、 構造化パーセプトロンと bilevel BCE で学習する。T2 以外の 6 層は supreme2 系の決定的モジュール（閾値・状態機械・HGF 階層フィルタ）を流用する。 本ページは specs/ARCHITECTURE.md・src/supreme/neupsl.py・src/supreme/core.py・ ADR 0052〜0058・reports/situations_v1-eval-20260722/results.json に準拠し、 表示される数値はすべてページ内に埋め込んだデータから計算している（手書き数値なし）。

深掘り①：本来型 NeuPSL の 3 要素

① ニューラル述語 — 微小 MLP が生特徴から軟真理値を出す

述語は 入力 1〜4 次元 → 隠れ （tanh）→ sigmoid の 2 層 MLP。決定的擬似乱数（sin ベース）で初期化し、 出力バイアス −2.0 で「未学習時はほぼ沈黙、学習で立ち上がる」。現在 述語 （supreme3 初出 9 + ADR 0057 新設 3）。

観測述語 個（入力値をそのまま真理値に使う：siren/alarm/vehicle/speech/risk_*/approaching/… ＋ ADR 0057 で t1_depart/t1_pass 追加）は MLP を通さない。 開述語（推論対象）は Mode(値)/Role(値)/Rel(値)。

② Łukasiewicz ルール 本 — グループ別

意味論は Łukasiewicz 緩和：連言 I(A∧B)=max(0, a+b−1)、否定 ¬a=1−a、 含意 A→B の違反量 max(0, I(A)−I(B))。「重み×違反量」の総和をエネルギーとする。重みは学習対象（下表は初期値）。

グループ本数代表ルール（初期重み）意味
本数の突き合わせ（正直な整合）: docs/NEUPSL_RULES.md は表題「全 28 本」のままだが、これは supreme3 世代の値である。 ADR 0053 で ⊤→既定クラス の prior ルール 3 本を「クラス別負事前」へ置換（→ 25 本）、 ADR 0057 で新語彙ルール 4 本を追加（→ 29 本）。src/supreme/neupsl.py の RULES を数えた 現在の真値は 本。詳細は NEUPSL_RULES.md（表題は要更新）。

③ HL-MRF 結合 MAP 推論 — シナリオ全体を一つの最適化に

シナリオ内の全フレーム × 3 層（mode + role + rel ）の開述語を、 二乗ヒンジ（p=2）+ εI Tikhonov のエネルギーを持つ HL-MRF として同時最適化する。 解法は射影劣勾配降下（層ごとに確率単体へ射影・ステップ 0.20/√(1+0.15t)・最大 200 反復・変化量 1e-3 未満で決定的早期終了）。 時間持続ルール Mode(f−1,m)→Mode(f,m) が (フレーム数−1)× モードぶん接地され、 これがシナリオ全体を一つの結合 MAP 問題に束ねている（真の集合推論）。全経路が決定的（乱数・時刻なし）。

深掘り②：学習レシピ（4 段パイプ）

ADR 0056（supreme7 研究世代）の知見： 寄与は 事前学習 ≫ 二乗ヒンジ ≫ その他。 性能源泉はニューラル述語のラベル蒸留事前学習と二乗ヒンジのポテンシャル整形にあり、role は AddrEv 等の少数述語に一点依存、 mode/rel は語彙上限 0.85 前後で学習残余が大きい。

N3（PRIMARY）レシピの実測時間（results.json）：t3/scene 学習 s ／ T2 基礎 6 エポック s ／ bilevel 2 エポック + ≥ガード s。≥ガード（最大 400 練習シナリオ）で 学習 vs 事前重み を比較し、学習が事前重みを下回れば事前重みを採用する（学習が悪化させない担保）。

深掘り③：s2 → s8 系譜（coverage_v3 8 層平均・別土俵）

下の値は coverage_v3 土俵の 8 層平均であり、situations_v1（本ページ上部の KPI）とは別土俵。世代の追加要素と ADR を併記する。

supreme4 が手調整ルール（s2 0.6464）を 8 層平均で初めて上回った学習系。s7 は研究世代（アブレーション RQ1〜5・スコア更新なし）。 s8 は語彙拡張だが、coverage_v3 では +0.0005 の微増にとどまる（新クラス回収が限定的なため・後述）。 situations_v1（別土俵）の同エンジン実測は N3 pooled / N3-std 。

深掘り④：strict ゲートと F-015 アダプタ

strict_gt_conformance ゲート（ADR 0050）

  • ON（既定）＝ strict 系オーバーライド（ADR 0043〜0048＝GT 生成器 gt_derive.py の規則 f の写し）を view に適用。 gt_derive 系コーパスの回帰・契約適合（spec-conformance）検証用。ON のまま能力を測ると循環（ADR 0049 撤回の再汚染）。
  • OFF（能力評価の正規）＝ strict 写しをスキップし、T2 を NeuPSL 結合 MAP 経路 （core._run_one_scenario_neupsl）へ通す観測ベース経路。

F-015 アダプタ（ADR 0058・core 無変更）

  • preflight が engine 実行前に契約違反を明示拒否： bad_versionts_regressionframe_count_mismatchtype_break。 version は決して書き換えない（洗浄すると拒否できなくなる）。
  • 非違反 eval を strict_gt_conformance:False で実走し harness.score で per-suite/pooled 採点。違反は分母から除外し rejection_acc で別採点。
監査 round1（needs_fix）P0 の是正（正直に記録）: P0-2＝ t3/scene 学習の mode 系列を、strict ON view（循環リスク）由来から strict OFF 公開 API（run_supreme_scenarios(..., strict_gt_conformance:False)）由来へ変更。 P0-1＝ 全 train 非違反入力を fit 前に preflight し、false reject を incident 化して学習から除外 （今回は train_false_reject 件）。strict OFF 学習化により N2/N3/N3-std の t3/scene params と最終数値は旧測定から変わり得る。

深掘り⑤：語彙拡張の現状（ADR 0057 の正直な評価）

ADR 0057 は mode に uncertain、relation に departing/unrelated を語彙追加し、 新述語 UncEv/DepEv/FarEv と新ルール 4 本（ 本へ）、T1 の pass/depart を観測特徴として結線した。 経路は通したが回収は限定的である：

  • uncertain は一部のみ回収。
  • departing/unrelated は現特徴（t1_depart・距離）では分離が不十分。relation ラベルの約 48% を占めるにもかかわらず（ADR 0058）。
  • 語彙上限（理論上 mode/rel とも 1.0）撤廃の実効化には、新述語向け特徴拡充（Δ距離系列・リンク不在の明示）と蒸留ターゲット再設計が前提。これはバグではなく既知の設計限界。

評価の土俵と規律

  • 別土俵の明示：situations_v1 は world-first 生成・潜在世界 W 由来 GT。coverage 系と数値を並べない。引用は suite+split+測定日。
  • 4 構成：N1（事前重み）/ N2（既定 10ep T2）/ N3（PRIMARY・基礎 6+bilevel 2 手配線） / N3-std（std/train 80 本のみ）。
  • rejection 別採点：契約違反を 8 層採点の分母から除外し、明示拒否の当否のみを rejection_acc で測る（eval /＝）。
  • 決定性・堅牢性：各 config で先頭 5 本を 2 回実走し view 完全一致・crash 0 件を確認。

per-suite の overall（N3・機械計算）：

dcp（観測が嘘をつく罠）・crp（破損下の Safety Latch）の低値は設計意図であり天井は構造的に 1.0 未満。 scene_regime の emg/crp が低いのも同様に破損・緊急スイートの特性。

正直な注記

既存テスト失敗（F-015 と無関係）: SupremeParams.learnable_param_count() ＝ （NeuPSL + t3 + scene ）が閾値 360 を超過し、 F-014-1 の param≪data ガードテスト（tests/test_Phase1_learning_wiring.py）が master 基点で既に失敗している （ADR 0057 の新ルールで学習パラメータが増加）。F-015 の全変更を退避しても再現する既存の失敗であり、F-015 のテスト自体は全緑。
  • GT は規則生成のため、学習が獲得するのは「仕様規則への汎化」。能力の主張には独立ラベラ（f_blind）照合の併記が要る（ADR 0049 継承）。 situations_v1 はその循環を GT の潜在世界直接導出で構造排除した別土俵。
  • モチーフ有限性：train/eval は同一 50 モチーフの別パラメタ。最終確定測定（seal）には完全新作モチーフが必要（生成器側の宿題）。
  • MAP は近似解：凸緩和の劣勾配法で反復上限内の決定的近似解である。
