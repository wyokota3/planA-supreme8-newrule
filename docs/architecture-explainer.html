環境音から状況を読み取り、8 層の EPI を出力する決定的エンジン supreme8 の仕組みを解説します。中核は、T2 の 3 層（場の様相 mode・音源の正体 role・関係 relation）を本来型 NeuPSL（ニューラル述語と論理ルールと結合 MAP 推論を組み合わせた枠組み）で解くところにあります。あわせて、能力評価の土俵 situations_v1（strict OFF・別土俵）で測った結果も示します。

この解説の全体像（まず要点から）

supreme8 は、環境音の時系列から状況を読み取り、8 つの層（risk_tier / t1_state / t2_mode / t2_role / t2_relation / t3_hypothesis / quality_regime / scene_regime）を出力する決定的なエンジンです。同じ入力からは必ず同じ出力が出るように設計されています。

このエンジンの中心にあるのは、T2 の 3 層（mode・role・relation）を本来型 NeuPSL で解く部分です。NeuPSL は次の 3 つの部品からできています。1 つ目は、生の特徴を 0〜1 の軟らかい真理値に直すニューラル述語です。2 つ目は、Łukasiewicz 緩和（論理式を連続値で扱えるようにする方法）にもとづく重み付きの論理ルールで、いまは 本あります。3 つ目は、シナリオ内の全フレームと 3 層をまとめて最適化する結合 MAP 推論（HL-MRF）です。T2 以外の 6 層は、prepass（risk・t1・quality・scene を観測式・HGF・状態機械で求める前処理）と T3 統合が受け持ちます。

今回の主役である N3（PRIMARY）構成では、全 8 層をならした pooled overall が でした。層ごとに見ると、quality（）・t1（）・role（）が高く、mode（）と t3（）が低いという傾向でした。以下では、①外観、②8 層対応表、③NeuPSL の共通基盤、④各層の詳しい解説、の順で読み解いていきます。

③ NeuPSL という共通の土台（3 つの部品と学習レシピ）

T2 の 3 層（mode・role・relation）は、どれも同じ NeuPSL という仕組みの上で解かれます。層ごとの解説に入る前に、その共通の土台をまとめて説明します。NeuPSL は「ニューラル述語」「論理ルール」「結合 MAP 推論」の 3 つからできており、下の図（a）は入力から出力までを左から右へ 6 つのゾーン（①入力と観測 ②ニューラル知覚 g_θ ③神経-記号インターフェース ④PSL プログラムと接地 ⑤Deep-HL-MRF エネルギーと結合 MAP ⑥ターゲット述語と下流出力）に並べたものです。観測述語 個は MLP を通さず入力値をそのまま真理値として使い、ニューラル述語 個だけが小さな 2 層 MLP（入力 1〜4 次元 → 隠れ （tanh）→ sigmoid・出力バイアス −2.0 の沈黙起点）を通ります。学習の流れは推論の流れとは別物なので、あとで図（b）に分けて示します。

凡例。 矢印の意味と、述語の役割を表す枠の形は次のとおりです（色だけに頼らず形で区別します）。

実線 = 実行時（推論） 破線 = 教師・勾配・更新 点線 = オフライン・任意 平行四辺形 = 入力 太緑枠 = ニューラルモデル（中核） 二重青枠 = ニューラル述語 二重緑枠 = ターゲット述語 付箋 = ルールテンプレート 六角形 = 結合 MAP 推論

学習レシピ（4 段のパイプライン）

T2 の各層は、次の 4 段のパイプラインで学習されます（上の学習図（b）の 3 段に対応し、②の中で二乗ヒンジと指数勾配を分けて数えると 4 段になります）。段ごとに役割が違い、前の段の成果を次の段が受け継いでいきます。

ADR 0056（研究世代）でわかったこと。 各要素の効きを切り分けたところ、寄与の大きさは「事前学習 ≫ 二乗ヒンジ ≫ その他」の順でした。つまり性能の源泉は、ニューラル述語をラベル蒸留で事前学習すること、そして二乗ヒンジでポテンシャル（罰の形）を整えることにあります。役割別に見ると、role は少数の述語に強く依存し、mode と relation は語彙の上限近くで学習しきれない残りが大きい、という傾向でした。

N3（PRIMARY）レシピの実測時間（results.json より）は、次のとおりです。t3/scene の学習に 秒、T2 の基礎 6 エポックに 秒、bilevel 2 エポックと ≥ ガードに 秒かかりました。≥ ガード（最大 400 練習シナリオで判定）では、学習後の精度 と事前重みの精度 を比べ、学習が事前重みを下回った場合は事前重みを採用します。これは、学習がかえって悪化させないための保険です。

結果を読むために必要な測定条件（strict OFF と監査是正の要点）。

strict OFF は必須です（strict_gt_conformance=False・ADR 0050）。strict ON（GT を導く規則 f の写し）を使うと、ADR 0049 で撤回した循環スコアが再発してしまいます。そのため能力評価では、T2 を NeuPSL の結合 MAP 経路に通します。

監査 P0 の是正を反映しています。 t3/scene 学習に使う mode 系列を、strict ON の view から strict OFF の公開 API（run_supreme_scenarios(..., strict_gt_conformance=False)）由来へ変えました（P0-2）。さらに、学習に使う非違反入力を fit の前にすべて事前検査し、誤って拒否されたもの（false reject）は学習から除外します（P0-1。今回の train_false_reject は 件でした）。

拒否は別枠で採点します。 契約に違反する eval 入力は 8 層採点の分母から外し、明示的に拒否できたかどうかだけを rejection_acc で測ります（eval では / ＝ でした）。

④ 8 層それぞれの詳しい解説（今回の結果と、その構造的な理由）

ここからは 8 層を 1 つずつ見ていきます。各層について「何を当てる層か」「今回の結果」「supreme8 はどう決めるか」「解釈」「よくあるつまずき」の順に説明します。確証のない部分は「推定」と明記します。

N3 の eval では、契約に適合した 235 シナリオ、4,057 フレームを採点しています。層別 accuracy の分母はスイートに含まれる全フレームで、pooled の分母は 6 スイートを合わせた全 4,057 フレームです。

risk_tier層 1prepass

ひとことで言うと: 音源が衝突リスクになるまでの切迫度を 3 段階で示す層です。

何を当てる層か音源までの余裕時間から見た、衝突リスクの段階を当てる層です。答えのラベルは info・caution・danger の 3 つです。

どう決めるかprepass の t0 が担当します。まず主トラックを選びます。siren（サイレン）があればそれを優先し、なければ最も近い（r_m が最小の）音源を選びます。次に、その TTC（衝突までの推定時間）を純粋な閾値で判定します（ADR 0045）。具体的には、siren → danger、ttc < 2.0s → danger、ttc < 8.0s → caution、それ以外は info とします。NeuPSL は通さず、状態も持たない決定的なルールです。

解釈グラフで最も高いのは （）で、最も低いのは （）です。この差は、各スイートの TTC 分布と GT の区切りが純閾値にどれだけ合うかで生じたと推定します。観測にもとづく決定的なルールであり、GT の写しを使っていないため、循環のリスクはありません。

よくあるつまずき: この層を NeuPSL の学習結果と捉えがちですが、実際には prepass の固定閾値だけで決まります。

t1_state層 2prepass

ひとことで言うと: 音源の距離変化を追い、接近・通過・離脱を時系列で見分ける層です。

何を当てる層か音源が近づいているのか離れているのか、その運動状態を当てる層です。ラベルは idle・approach・pass・depart の 4 つです。

どう決めるかprepass の t1 状態機械が担当します。まず接近を、しきい値 ttc_threshold = clamp(12 + 3·pw_anom, [12,15]) で判定します。前の状態が approach だった場合は発散を調べ、(cur − min_seen) > 1.0 かつ (cur − prev_range) > 0.3 のとき、距離が近ければ（5m 未満）pass、遠ければ（10m 超）depart とします。さらにエピソードの approach_ratio で approach を固定し、hazard_trend で depart／idle を補正します。状態は外部から注入されて連鎖します。

解釈グラフで最も高いのは （）で、最も低いのは （）です。スイート間の差が比較的小さいのは、単一フレームではなく、距離の最小値と直前値を状態機械でつないで運動の向きを捉えるためだと考えられます。最低側の低下には破損や運動軌跡の構成差が影響したと推定します。

よくあるつまずき: 各フレームを独立に判定すると考えがちですが、直前状態とエピソード集約が次の判定へ引き継がれます。

よくあるつまずき: ラベル蒸留が推論時に GT を参照すると誤解しがちですが、GT 由来ターゲットを使うのは述語の事前学習時だけです。

t2_relation層 5NeuPSL

ひとことで言うと: 音源がユーザーへ話しかけているか、近づくか、離れるかなどの関係を示す層です。

何を当てる層か音源とユーザーの関係を当てる層です。ラベルは 6 種類あります：addressing_user / near_user / approaching / grouped / departing / unrelated。

どう決めるか述語 AddrEv［call_user, addr_link, near3, spk_link］・DepEv［t1_depart, range_n, approaching］・FarEv［range_n, near3, humans_n, spk_link］と、観測 approaching を使います。代表ルールは次のとおりです。 r_addr_rel (w2.5) AddrEv → Rel(addressing_user) r_appr_rel (w2.0) approaching → Rel(approaching) r_t1dep_rel (w3.0) t1_depart → Rel(departing) 〔ADR 0057〕 r_far_unrel (w2.0) FarEv ∧ ¬approaching → Rel(unrelated) 〔ADR 0057〕 たとえば r_far_unrel は、遠く、かつ近づいてもいないときに無関係と読む、という意味です。 上のグラフでは、これらの式が の証拠構成には合う一方、 では DepEv・FarEv の特徴不足が響いたと推定します。 結合 MAP のなかで、x_request_addr（Mode(conv_request)→Rel(addressing_user)）が mode との整合をとります。

解釈グラフで最も高いのは （）で、最も低いのは （）です。addressing・approaching・near はよく効きますが、ADR 0057 で足した departing・unrelated は、いまの特徴（t1_depart や距離）では分離が不十分で、回収が限定的です。この 2 つは relation ラベルの約 48% を占めるため、スイートのラベル構成がグラフの差へ表れたと推定します。これはバグではなく、ADR 0058 が記録した既知の設計限界です。

t3_hypothesis層 6T3 統合

ひとことで言うと: mode の時間的な並びをまとめ、シナリオとして何が続いているかを推定する層です。

何を当てる層か時系列で見た状況の仮説を当てる層です。ラベルは 10 種類あります：quiet_stable / conv_participating / sustained_alert / env_shift / env_start / crowd_tendency / traffic_unstable / hazard_declining / uncertain_context / alert_required。

どう決めるかprepass の後段にある t3 が担当します。まず NeuPSL が出した mode の系列を、有界窓（長さ ≤ W）とエピソード集約（持続する会話の比率・切替率・flip の累積・posterior の平均／分散／トレンド）に畳み込みます。次に局所ロジスティックで conv／traffic／quiet の 3 つの境界を作って argmax をとり、残りのクラスは規則層で割り付けます。エピソードは frame0 でリセットして初期化します。学習パラメータ は、予算 100 よりずっと少ない値です。監査 P0-2 の是正で、集約に入る mode 系列を strict OFF の公開 API 由来へそろえました。

解釈グラフで最も高いのは （）で、最も低いのは （）です。入力が NeuPSL の mode 出力なので、mode の品質にそのまま連動します。最高側では mode の群衆整合を時系列集約でき、最低側では mode の低下が下流へ伝わったと推定します。

よくあるつまずき: T3 が生の観測から独立に仮説を作ると考えがちですが、実際には上流の mode 系列を入力にするため、その誤りも引き継ぎます。

quality_regime層 7prepass

ひとことで言うと: 入力観測をそのまま信頼できるか、劣化しているか、遮断すべきかを決める層です。

何を当てる層か観測そのものの品質レジームを当てる層です。ラベルは GOOD・DEGRADED・BLOCK の 3 つです。

どう決めるかprepass の quality が担当します。h_q（と層 1 の事後分散 vol）を、優先順位を決めたチェーンで順に判定します（ADR 0014）。上から h_q<0.25→BLOCK、h_q<0.40 ∧ vol>0.05→BLOCK、h_q<0.55→BLOCK、h_q≥0.93 ∧ vol<0.01→GOOD、どれにも当たらなければ DEGRADED です。決定的な純関数です。

解釈グラフで最も高いのは （）で、最も低いのは （）です。8 層のなかで pooled accuracy が最も高く、優先順位チェーンが安定して働いています。最低側が下がるのは、破損した観測を GOOD にせず BLOCK／DEGRADED へ振り分ける境界が集中的に試されるためだと推定します。

よくあるつまずき: 各閾値を独立に評価すると考えがちですが、上から最初に成立した条件を採用する優先順位が結果を左右します。

scene_regime層 8prepass · HGF

ひとことで言うと: シーン全体が安定しているか、変化中か、悪化中かを持続的な揺らぎから判断する層です。

何を当てる層かシーン全体がどう変化しているか、そのレジームを当てる層です。ラベルは STABLE・CHANGING・DEGRADING の 3 つです。

どう決めるかprepass の scene が担当します。まず HGF の 3 層カーネルで、潜在水準 μ1（層 1）と log-volatility（対数のゆらぎやすさ・層 2）を階層的に推定します（層 2 が持続的な変化をとらえます）。これに持続性の特徴（nominal からのずれの漏れ積分）を加え、閾値で 3 クラスに分類します（DEGRADING を含みます）。学習するのは HGF のパラメータと閾値だけで（ は予算 100 よりずっと少ない値です）、監査是正のあとは strict OFF の view で fit します。

解釈グラフで最も高いのは （）で、最も低いのは （）です。HGF と持続性特徴は継続的な変化を拾えますが、破損時には Safety Latch が働くため、天井が構造的に 1.0 未満になります。最低側ではこの制約が強く表れたと推定し、低下自体は設計どおりです。

よくあるつまずき: 一瞬の変化だけで CHANGING になると考えがちですが、HGF の揺らぎと漏れ積分による持続性を合わせて判定します。

⑤ s2 から s8 への系譜

ここでは、世代ごとに何を足してきたかと、その世代の coverage_v3 8 層平均を 1 本の帯にまとめます。ただし coverage_v3 は situations_v1 とは別の土俵なので、両者の数値を並べて比べないでください。要点だけ先に言うと、s4 で学習系が初めて手調整ルール（s2）を上回り、s7 は研究世代（スコアの更新なし）、s8 は語彙の拡張です。

この帯の読み方。 左が世代、まん中がその世代で加えたこと（末尾に対応する ADR）、右が coverage_v3 の 8 層平均です。研究世代の s7 はスコアを更新していないため、右端は「—」と表示されます。

⑥ 評価の土俵（要点）

最後に、今回の評価をどう読むべきかを 4 点にまとめます。

  • 別の土俵であることを、はっきりさせます。 situations_v1 は world-first 生成で、正解は潜在世界 W に由来します。したがって coverage 系の数値とは並べません。引用するときは、スイート名・分割・測定日をそえます。
  • 4 つの構成で測っています。 N1（事前重み）、N2（既定 10 エポックの T2）、N3（PRIMARY。基礎 6 ＋ bilevel 2 を手配線したもの）、N3-std（std/train 80 本だけで学習）の 4 つです。層別解説で使った数値は、PRIMARY である N3 のものです。
  • 拒否は別枠で採点します。 契約違反の入力は 8 層採点の分母から外し、明示的に拒否できたかどうかだけを rejection_acc で測ります（eval では / ＝ でした）。
  • 決定性と頑健性を確認しています。 各構成で先頭 5 本を 2 回ずつ実走し、view が完全に一致すること、そして crash が 0 件であることを確認しました。

⑦ 正直な注記

既存テストの失敗について（F-015 とは無関係です）。 SupremeParams.learnable_param_count() は （NeuPSL ＋ t3 ＋ scene ）で、閾値 360 を超えています。そのため、param ≪ data を確かめる F-014-1 のガードテスト（tests/test_Phase1_learning_wiring.py）が、master 基点で既に失敗しています（ADR 0057 の新ルールで学習パラメータが増えたためです）。これは F-015 の変更をすべて退避しても再現する既存の失敗であり、F-015 自体のテストはすべて緑です。
