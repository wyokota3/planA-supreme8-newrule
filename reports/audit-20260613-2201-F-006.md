#### 【重大指摘 T0-1】safety latch が risk_tier を danger に上書きする規則が baseline 実コードと乖離している

**事実(baseline 実コード)**: baseline では `risk_tier`(採点対象フィールド・ADR 0012)は `_determine_risk_tier(kind, min_TTC_s)` の出力のみで決まり、**safety latch は risk_tier を上書きしない**。

引用 `external-data/planA-baseline/src/ns_epi/t0.py:203-223`:
```python
# risk_tier 判定(g_global 非依存)
risk_tier: str = _determine_risk_tier(kind, min_TTC_s)   # latch を含まない
...
latch: bool = safety_latch(min_TTC_s=min_TTC_s, kind=kind)
# risk_safe 計算(latch は risk_safe にのみ影響)
if latch:
    risk_safe: float = risk_raw
else:
    risk_safe = min(1.0, risk_raw + (1.0 - g_global) * 0.2)
t0_candidate: dict[str, Any] = {
    ...
    "risk_tier": risk_tier,   # ← latch で上書きされていない _determine_risk_tier の出力
}
```
`_determine_risk_tier`(baseline `t0.py:122-148`)には latch 処理が存在しない。latch は別関数 `safety_latch`(baseline `t0.py:42-59`)で boolean を返すだけで、`risk_safe`(数値特徴)にしか作用しない。

**採点される field はどれか**: baseline の8層評価ビューは `runner.py:280` で `"risk_tier": str(t0_candidate["risk_tier"])` を採用=latch 非適用の `_determine_risk_tier` 出力がそのまま採点される。emit も同じ(`emit.py:1045`)。

**実トレースの実測**: `external-data/planA-baseline/results/trace/trace.json` の siren フレーム実測:
- `kind=="siren"` ∧ `risk_tier=="caution"` = **54 フレーム**(例 `trace.json:3693-3695` range_m=60.0 / `:4098-4100` range_m=48.0。遠方=高 TTC siren で info→caution 引き上げ止まり。danger ではない)
- `kind=="siren"` ∧ `risk_tier=="danger"` = 39 フレーム(低 TTC siren で kind 閾値 danger≤2.0 に純粋にヒット)

**supreme の挙動**: `src/supreme/t0.py:85-86` の `or kind == "siren"` により、上記 54 フレームの siren-caution は**すべて danger に上書きされる**。すなわち supreme の risk_tier は baseline と**少なくとも 54/210 フレームで不一致**になる(siren-caution → danger)。さらに min_TTC≤0.8 の非 siren ケースでも上書きが起きるが、kind 閾値 danger が大半をカバーするため siren-caution が主たる乖離源。

**影響**: risk_tier は強い項目維持(δ_strong ≤ 0.02・3層平均の1つ)の採点対象(ADR 0012)。baseline risk_tier acc=0.9333(`results/l04-ours/per_layer.json:2`)。54 フレーム/210 が baseline と乖離する設計は、F-006-1(δ_strong ≤ 0.02)を F-013 で**落とす蓋然性が高い**(54/210≒0.257 の出力差。仮に GT 上 caution が正解の siren フレームが多ければ acc が大幅低下しうる)。

**判定**: T0 = **部分的に実装(ADR 0017 文面には忠実だが baseline 実コードと乖離)**。

**根本原因の所在**: 乖離は実装バグではなく、**ADR 0017 決定3 T0 の記述**(`decisions/0017-f006-strong-reimplementation.md:38`「safety latch(...): min_TTC ≤ 0.8 ∨ kind=="siren"」を risk_tier を決める段の一つとして列挙)が、baseline の「latch は risk_tier を上書きしない・risk_safe にのみ作用する」という実装事実と食い違っていることにある。実装者・テストは ADR 0017 に忠実なため、本指摘は**ADR 0017 の T0 ルール定義の是正**が正しい対処であり、実装/テストの単独修正で済ませてはならない(SPEC・ADR の整合が崩れる)。ADR 0017 決定3 は「baseline ルールを忠実再現」を目標と宣言しているため、文面と baseline 実コードの不一致は ADR 自身の前提に反する。
