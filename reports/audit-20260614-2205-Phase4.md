## 検証1: h_q 死配線の診断が正しいか → pass

**ADR の主張**(`decisions/0026-phase4-hq-uncertain-gate.md:37-44`):
> 直接経路: 0 / 420 フレーム — posterior を 0→1 に振っても t3 出力は一切変わらない。
> `episode_features` は posterior を `posterior_mean/var/trend` に集約するが、`classify_t3` も
> `_rule_hypothesis` もそれを**一度も読まない**。

**コード照合**:

`classify_t3`(`src/supreme/t3.py:412-414`)が読む特徴は conv_ratio / switch_rate / flip_accum の3つのみ:
```python
conv_ratio = float(features.get("conv_ratio", 0.0))
switch_rate = float(features.get("switch_rate", 0.0))
flip_accum = float(features.get("flip_accum", 0.0))
```
スコア式(`src/supreme/t3.py:423-425`)にも posterior_mean/var/trend は一切現れない:
```python
conv_score = w_conv * conv_ratio + bias_conv
traffic_score = w_switch * switch_rate + w_flip * flip_accum + bias_traffic
quiet_score = bias_quiet
```
`_rule_hypothesis`(`src/supreme/t3.py:503-530`)は `state.mode_window` の mode 出現割合のみを参照し、posterior を読まない。

→ posterior(h_q)が `episode_features` で集約(`src/supreme/t3.py:309-317` の post_mean/var/trend)されるが、分類器・規則層のどちらも読まない、という診断は**コードで確認できる事実**。

**診断レポートの実測**(`reports/phase4-hgf-diagnose-after.md:29`):
> posterior を 0/1 に振っても t3 が変わったフレーム: **19 / 420**

ADR L39 は「0 / 420」と書くが、実測レポートは「19 / 420」。この 19 は **本ゲート結線後**の挙動(posterior<0.40 で env→uncertain に化けるフレーム)を捉えた数。ADR の「0/420」はゲート結線**前**の死配線状態の記述で、文脈上は整合する(ADR は「修正前は 0、修正で結線」を述べている)。ただし**ADR が引用する診断レポートのファイル名と実在ファイルの数値(19/420)が、ADR 本文の 0/420 と表面上食い違う**ため、読者を誤認させうる(検証1の判定自体は pass だが、後述の参照ズレと併せて記録)。

**修正がその死配線を結線するか**: `step`(`src/supreme/t3.py:604-606`)で base 仮説確定後に posterior を読み、env 系のみ uncertain へ書き換える:
```python
posterior = float(mode.get("posterior", 1.0))
if posterior < _UNCERTAIN_HQ_GATE and hypothesis in _UNCERTAIN_GATE_TARGET:
    hypothesis = UNCERTAIN_CONTEXT
```
これは「h_q を t3 出力へ届ける」結線であり、診断が指摘した死配線を結線するもの。**判定: pass**。

## 検証2: ★閾値 0.40 が過適合でないか★ → 条件付き pass(分離点は引用確認・plateau は未裏付け)

**ADR/コードの主張**(`decisions/0026-phase4-hq-uncertain-gate.md:69-71`、`src/supreme/t3.py:469-473`):
> GT=uncertain の h_q max 0.530、真 env の h_q ≥ 0.66、GOOD 品質 h_q ≥ 0.594。
> 0.40 は uncertain と env/GOOD を分離する谷で tau∈[0.35,0.50] は held-out 同値の平坦域。

### 2a. 品質クラス分離点(原理) → 引用で裏付けあり

`reports/phase4-hgf-diagnose-after.md:47`(計測3・GT t3 クラス別 h_q 分布):
```
| uncertain_context | 9 | 0.0023 | 0.0871 | 0.5297 |
```
→ uncertain の h_q 中央 **0.0871**・max **0.5297**(ADR の「中央 0.087・max 0.530」と一致)。

同レポート L48(env_start)・L45(env_shift):
```
| env_shift | 15 | 0.7384 | 0.9205 | 0.9415 |
| env_start |  7 | 0.6582 | 0.9267 | 0.9417 |
```
→ 真 env 系の h_q **min 0.6582**(ADR の「≥0.66」とほぼ一致、厳密には env_start min=0.6582)。

`reports/phase4-hgf-diagnose-after.md:12`(計測1・GOOD 品質):
```
| GOOD | 154 | 0.5944 | 0.9407 | 0.9491 | 0.9286 |
```
→ GOOD 品質の h_q **min 0.5944**(ADR の「≥0.594」と一致)。

**結論**: uncertain(max 0.53)と env/GOOD(min 0.59〜0.66)の間に谷があり、0.40 はその谷の中。**特定フレームへの合わせ込みではなく、品質クラス分離点として引用で裏付けられる**。

### 2b. plateau(tau∈[0.35,0.50] で held-out 同値) → ★本差分の証拠集合に裏付けが存在しない★

ADR L70・コード L472 は「tau∈[0.35,0.50] は held-out 同値の平坦域」と主張するが、**閾値スイープ(複数 tau で held-out acc を並べた計測)が `reports/` のどの Phase4 レポートにも存在しない**(`phase4-hgf-diagnose-after.md` / `cv-phase4-after.md` / `dev-eval-phase4-after.md` のいずれにも tau スイープ・plateau の表/数値なし。横断 grep で `plateau` / `平坦域` / `tau` / `0.35〜0.50 同値` の一致ゼロ)。

→ plateau 主張は**分布(2a)からの定性的推論**であって、計測で示された平坦域ではない。max(uncertain)=0.53 と min(env)=0.59 の間隔から「0.40〜0.50 のどこでも同じ分類になる」ことは分布上は妥当だが、ADR が「held-out 同値」と数値主張する以上、tau スイープ表で裏付けるべき。**過適合ではないが、ADR の plateau 文言は現状エビデンス不足**。

### 2c. CV held-out で +0.033 → 引用で裏付けあり(ただし ADR の「+0.0333」は学習列のこと)

before/after の CV レポートを突合:

- `reports/cv-phase4-after.md:16,32`(生成 22:00 = **ゲート結線後**): t3 held-out 既定 **0.3905** → 学習 **0.4429**

→ ゲート効果は held-out で 既定 +0.0334(0.3571→0.3905)、学習 +0.0334(0.4095→0.4429)。ADR L77 の「t3 学習 0.4095→0.4429(+0.0334)」とコード L473 の「0.4095→0.4429(+0.0333)」は **学習列の before→after** を指し、整合する。

**注意**: `cv-phase4-after.md:16` 単体を読むと「0.3905→0.4429(+0.0524)」と見え、これは after の {既定→学習} の差(学習利得)であってゲート利得ではない。ゲート利得は before/after の2レポート間差分。ADR の数値は正しいが、ゲート利得の根拠を1ファイルで完結させていないため追跡が要る(参照ズレと併せ後述)。

## 検証3: ★env 限定スコープが原理的か test 回避か★ → 原理性 pass / 偽陽性ゼロは未裏付け

### 3a. env 限定が原理的か → pass(core で確認)

**ADR/コードの主張**(`src/supreme/t3.py:476-481`):
> env_start/env_shift は上流 env_change mode から立つが、その env_change は `core._mode_logits` が
> **h_q<0.5 で積む**観測劣化シグナル由来。

診断スクリプトが core の該当経路を再現している(`scripts/run_phase4_hgf_diagnose.py:181`):
```python
logits = core._mode_logits(snap, risk_tier, approaching, hq_fixed)
```
コメント(同 L98-99):
> core の _mode_logits は h_q<0.5 で env_change logit を積む。

→ env_change mode が h_q<0.5 の観測劣化から立つことは、診断が core 内部関数 `_mode_logits` を直接呼んで検証している。env_start/env_shift だけが「観測劣化を環境変化と過剰断定」しうるクラスで、それだけを uncertain へ是正するのは**原理的**(quiet/conv/traffic/安全警戒系は h_q 由来でないので触らない)。**判定: pass**。

### 3b. test 回避の便宜的スコープか → 回避ではない

ADR L84 は env 限定の理由を:
> `test_F009_1_different_reset_list_can_change_output` が要求する reset 感度=quiet フレームの分岐を保つ

と述べる。該当テスト(`tests/test_F009_reproduce.py:114-115` 周辺の reset 列差し替え)は **quiet/conv フレームの reset 分岐**を検証する。本ゲートは env 系のみ書き換えるので、このテストが触る quiet/conv フレームには影響しない。

**判定**: env 限定の一次理由は 3a の原理(h_q→env_change 経路)であり、テスト互換は副次的整合に過ぎない。**「広域ゲートが本来妥当だがテストを壊さないために env に絞った」という構図ではない**。広域ゲート(全クラスを posterior<0.40 で uncertain 化)は、quiet フレーム(観測品質でなく静穏で posterior 低)を巻き込むため**原理的に不適**(`src/supreme/t3.py:481-482` のコメントが明示)。→ **test 回避ではない・原理的**。

### 3c. ★偽陽性ゼロ(regression 0)が CV/全fold で確認されているか★ → ★ADR 主張の文言が引用元に存在しない★

**ADR の主張**(`decisions/0026-phase4-hq-uncertain-gate.md:80`):
> **偽陽性ゼロ**: CV 全 fold で「正答の env を uncertain へ巻き込む regression = 0」を確認。

コード L473 も同旨を「reports/cv-train-* と phase4 診断」を根拠に主張。

**引用元の照合**: ADR が根拠に挙げる `reports/cv-phase4-after.md` を全文検索したが、**「偽陽性」「regression」「巻き込む」「正答の env」という文言・計測が一切存在しない**(grep 一致ゼロ)。`phase4-hgf-diagnose-after.md` にも同種計測なし。

むしろ CV の fold 別を見ると、`reports/cv-phase4-after.md:31`(fold 4):
```
| 4 | ...ns017〜ns020 | 84 | 0.4286 | 0.4048 | -0.0238 |
```
→ fold 4 は学習 acc が既定を **-0.0238 下回る**。これは「学習 vs 既定」の差であってゲートの偽陽性とは別軸だが、CV レポートには **ゲート前後でクラス別に何件が env→uncertain に変わり、そのうち何件が正答 env を誤って潰したか(=偽陽性)** を示す表が無い。

**判定**: 「偽陽性ゼロ」は ADR/コードの**主張**としては明確だが、**引用可能な計測が本差分の証拠集合に存在しない**。検証4の判定基準「CV/全fold で確認されているか」に対しては、**引用できない=未裏付け**と判定する。これは「偽陽性が出ている」という意味ではなく、「ゼロであることを示す計測が添付されていない」という意味(差分監査の規律: 引用できないものは未確認)。
