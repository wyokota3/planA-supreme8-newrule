## T0-1 解消判定(引用付き)

### 検証項目1: risk_tier から safety latch が完全除去され、閾値テーブル + siren 下限のみか

**是正前(初回監査が指摘した実コード・`reports/audit-20260613-2201-F-006.md:64-69`)**:
```python
# safety latch(品質非依存の構造的強制): min_TTC <= 0.8 OR kind == "siren"。
if ttc <= _LATCH_TTC or kind == "siren":
    tier = DANGER
```

**是正後(現 `src/supreme/t0.py:80-94`)**:
```python
caution_th, danger_th = _THRESHOLDS.get(kind, _DEFAULT_THRESHOLDS)

# kind 別 TTC 閾値判定(<= で境界を含む)。
if ttc <= danger_th:
    tier = DANGER
elif ttc <= caution_th:
    tier = CAUTION
else:
    tier = INFO

# siren 下限: siren が info 判定なら caution へ引き上げ。
if kind == "siren" and tier == INFO:
    tier = CAUTION

return tier
```

**判定: 解消済(完全除去)**。

機械確認:
- `src/supreme/t0.py` 全文に `_LATCH`・`0.8`・`or kind == "siren"`(latch 条件)が**存在しない**(grep 確認: `_LATCH`/`0.8` ヒット 0 件)。
- `tier = DANGER` の出現は `src/supreme/t0.py:84` の**1箇所のみ**で、これは `if ttc <= danger_th:`(kind 別 danger 閾値)の分岐内。latch 由来の上書きではない。
- siren の扱いは `:91-92` の「siren 下限(info→caution 引き上げ)」のみ。**siren を danger に強制する規則は無い**。
- risk_tier の決定経路は (1) 主トラック選択 `:72`(siren 優先・なければ最小 r_m、`_select_main_track:97-108`)→ (2) kind 別閾値テーブル `:80-88`(`_THRESHOLDS:48-54`)→ (3) siren 下限 `:91-92` の3段のみ。latch を含まない。

**baseline 採点 risk_tier(`_determine_risk_tier`)との一致**(初回監査 T0-1 で確定した baseline 事実との突合):
- siren 高 TTC → caution(siren 下限): `src/supreme/t0.py:91-92` により siren が閾値判定で info になっても caution へ引き上げ止まり。danger に上書きされない。テスト `tests/test_F006_t0_risk_tier.py:257-266`(`siren, ttc=15.0` → caution)・`:269-277`(`siren, ttc=100.0` → caution)が固定。初回監査が示した baseline siren-caution(54フレーム・遠方/高 TTC siren)と整合。
- siren 低 TTC → danger は kind 別閾値経由: `src/supreme/t0.py:83-84`(`ttc <= danger_th=2.0`)により kind=="siren" の低 TTC は閾値で danger。テスト `tests/test_F006_t0_risk_tier.py:291-299`(`siren, ttc=1.5` → danger)が「latch ではなく siren danger 閾値 2.0 経由」を固定。初回監査が示した baseline siren-danger(39フレーム・低 TTC)と整合。
- 低 TTC 非 siren の danger も閾値経由(latch 非依存): テスト `:306-314`(speech 0.8 → speech danger 1.0 経由)・`:317-324`(vehicle 0.8 → vehicle danger 2.0 経由)・`:327-335`(default 0.5 → default danger 2.0 経由)。是正前 latch(`<=0.8`)が担っていた danger を全て kind 別閾値の責務に移し、根拠を閾値に明示。

→ 是正後の risk_tier は ADR 0017 追記(`decisions/0017-...md:79-83`「safety latch は risk_safe のみ・risk_tier は `_determine_risk_tier` の出力 = 閾値 + siren 下限」)と一致する。初回監査が定量化した 54/210 フレームの danger 誤上書きは**設計上消滅**した。

ドキュメント整合も是正済み:
- `src/supreme/t0.py:20-23` docstring が「safety latch は risk_tier に適用しない(ADR 0017 追記・監査 T0-1)」を明記。
- `tests/test_F006_t0_risk_tier.py:6-14` が是正の経緯(初回 latch を誤記と認め除去)を明記し、是正後挙動を契約化。
- `specs/SPEC.md:141`「safety latch は risk_safe 用＝採点外・除外。ADR 0017 追記」と一致。
- ADR 是正 → test-writer → implementer → 差分監査 の修正ループ(ADR 0017 追記 `:87`)を踏襲。実装/テスト単独修正でなく ADR・SPEC・テスト・実装が同期している。
