## 検証 1(最重要): 忠実再現か過適合か

### 判定: 忠実再現(恒久規則の再現)。過適合(v021_core 特定フレームへの合わせ込み)ではない。

**根拠 1-A: 新コードは構造判定のみで ts/シナリオ依存条件を持たない(引用確認)**

`src/supreme/core.py:241-255`:
```python
def _has_object_type(snap, type_):
    return any(t.get("type") == type_ for t in _object_tracks(snap))


def _has_vehicle_evidence(snap):
    """role の has_vehicle 証拠(車両証拠)を抽出する(baseline t2.py L187-192 忠実再現)。
    ...
    """
    return _has_audio_type(snap, "vehicle") or _has_object_type(snap, "vehicle")
```
- `_has_vehicle_evidence` は `audio track(type=="vehicle") ∨ object track(type=="vehicle")` の純粋な論理和。
- **ts / scenario_id / フレーム番号 / 特定 r_m 値 / 特定 ns0xx シナリオへの分岐は一切ない**。`snap` の構造(track の type フィールド)だけを見る決定的純関数。
- `_has_audio_type`(`core.py:237-238`)・`_has_object_type`(`core.py:241-242`)も `t.get("type")==type_` の構造述語で同様。

**根拠 1-B: baseline 恒久規則の意味論との一致**

- 新 `_role_evidence`(`core.py:282-294`)は `has_vehicle` 以外(`has_siren`/`has_alarm`/`has_speech`/`speaking`/`min_range`/`linked_speech_score`)を一切変えていない。変更点は `has_vehicle` の抽出経路のみ。

- ADR 0017(`decisions/0017-f006-strong-reimplementation.md:25-26`)は「証拠抽出(段1)は**上流共有基盤**でスコープ外」と規定し、同 ADR は baseline `external-data/planA-baseline/src/ns_epi/{t0.py,t1.py,t2.py}` を忠実再現対象として参照(`:6`)。SPEC `F-006`(`specs/SPEC.md:378`)も「baseline ルールを忠実再現」と明記。

## 検証 2: 偽陽性ゼロ(GT≠source_vehicle を source_vehicle に誤予測していないか)

### 判定: 過剰予測ゼロ(確認済)。

**根拠 2-A: 算術的整合(取りこぼし回復のみ・新規誤予測なし)**

- pre-fix(`reports/dev-eval-20260614-2036.md:33`): t2_role 既定 acc = **0.8714**(= 183/210)。
- post-fix(`reports/dev-eval-20260615-0241.md:33`): t2_role 既定 acc = **0.9571**(= 201/210)。
- 差 = +18 件 = ちょうど診断レポートが「B 修正可」とした `source_vehicle→unknown` の **18 件**(`reports/role-diagnose-20260615-0233.md:309, 317, 323`)。
- **もし object-vehicle 追加で 1 件でも GT≠source_vehicle のフレームを source_vehicle に誤って flip させていたら、正味の利得は 18 を下回る**。実測が +18 ちょうど = 18 件回復・新規誤予測 0 と整合する。

**根拠 2-B: r1 elif 構造による誤予測抑止(引用確認)**

`src/supreme/role.py:98-102`:
```python
    # 緊急音優先: has_siren OR has_alarm -> source_alarm / elif has_vehicle -> source_vehicle。
    if has_siren or has_alarm:
        logits[SOURCE_ALARM] = logits.get(SOURCE_ALARM, 0.0) + _W_ALARM
    elif has_vehicle:
        logits[SOURCE_VEHICLE] = logits.get(SOURCE_VEHICLE, 0.0) + _W_VEHICLE
```
- `has_vehicle` は **`elif`** 枝。siren/alarm が共在する object-vehicle フレーム(診断の `source_vehicle→source_alarm` 4 件・`source_vehicle→unknown` のうち alarm 共在分)では source_vehicle は発火せず、誤って vehicle に倒すことはない(緊急音優先が維持される)。
- speech 共在フレームでは conv_strong/weak/linked が source_speech に積む(`role.py:104-123`)が、診断の 18 件は全て「audio∈{noise} ∨ siren/alarm 無し ∧ speech 無し」で object-vehicle 単独(`role-diagnose:118,126,134,172-284`)。よって source_vehicle が一意 argmax になり、speech フレームを vehicle に誤 flip する経路もない。

**根拠 2-C: 混同行列の整合**

- pre-fix 混同行列(`role-diagnose:49-54`)で supreme の `source_vehicle` 予測は 12 件、全て GT=source_vehicle 行(誤って他 GT を vehicle と予測した件数 = 0)。
- 本修正は「GT=source_vehicle なのに unknown に潰れた 18 件」を回復するもので、vehicle 予測の母数を 12→30 に増やすが、増分は全て GT=source_vehicle フレーム(診断 table 6 の B 区分 18 件が全て object-vehicle 在・緊急音無しと明記・`role-diagnose:309`)。
