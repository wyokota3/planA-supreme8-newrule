## 検証1（最重要）: 過適合か汎化か

### 採用根拠の引用確認（CV held-out 改善）

`reports/cv-train-20260614-2254.md:16`（結論表 t3 行）:
```
| t3_hypothesis | 0.3905 | 0.5333 | +0.1429 | **yes(+0.1429)** |
```
held-out 既定 0.3905 → held-out 学習 0.5333（Δ=+0.1429）。同レポート L32 の fold 集約も
held-out 全体 0.3905→0.5333 で一致。

### overfit gap=0.0000（held-out == in-sample）の引用確認

`reports/cv-train-20260614-2254.md:52`（過学習度表 t3 行）:
```
| t3_hypothesis | 0.3905 | 0.5333 | 0.5333 | +0.0000 |
```
→ in-sample 学習 acc **0.5333** == held-out 学習 acc **0.5333**、過学習度（in − held 学習）
**+0.0000**。これは「学習が in-sample に合わせ込んだ分が held-out で失われていない＝訓練データへの
過適合がゼロ」を意味する。

### 「v021_core への合わせ込み（in-sample 最大化）」でなく「held-out が汎化した」か

**判定: 汎化である。** 根拠:

1. **held-out 改善が in-sample 改善と同値**: もし grid 拡張が in-sample 最大化（合わせ込み）なら
   in-sample acc が held-out acc を上回る（gap>0）はず。実測は gap=0.0000（上記引用）。in-sample で
   稼いだ分が held-out でそのまま再現している＝v021_core 固有パターンへの過適合ではない。

2. **fold 全体で regression なし**: `reports/cv-train-20260614-2254.md:27-31` の fold 別 Δ は
   fold0 +0.1053 / fold1 +0.0000 / fold2 +0.0357 / fold3 +0.2281 / fold4 +0.1667。**全 fold で Δ≥0**
   （held-out で既定を一度も下回らない）。fold1 は ±0 だが負化していない。特定 fold への偏りで
   平均が押し上げられた形跡はない。

3. **較正の機序が「より低い flip ペナルティの選択」である**: `reports/conv-diagnose-20260614-2247.md:148-149`
   の 5b プローブ（**上流 mode 列を core 現行で固定**＝mode を一切変えない条件）:
   ```
   | w_flip_accum=1.0 | 0.4429 | 14 / 29 | ... |
   | w_flip_accum=0.0 | 0.5048 | 15 / 29 | ... |
   ```
   w_flip_accum を下げると conv→traffic の取りこぼしが解消。同 L156-158 が機序を明記:
   「単一の mode 切替(flip_accum=1)が w_flip_accum=4.0 で traffic_score を底上げし conv を負かす。
   w_flip_accum を下げると conv→traffic の取りこぼしが解消する(mode を一切変えずに)」。
   grid に `0.0, 0.25` を足すことは、この「より低い flip ペナルティ」を fit が**選べる**ようにする
   探索空間の拡張であり、特定フレームのラベルを直接埋め込むものではない。

4. **classify_t3 の構造は単調**（`src/supreme/t3.py:423-424`）:
   ```python
   conv_score = w_conv * conv_ratio + bias_conv
   traffic_score = w_switch * switch_rate + w_flip * flip_accum + bias_traffic
   ```
   w_flip_accum は flip_accum（連続特徴）の単調係数であり、grid 拡張は「係数を下げられる」だけ。
   新たな特徴・新たな分岐・GT 個別の if 文は追加されていない（オーバー実装の検出§参照）。

**結論**: held-out==in-sample（gap=0.0000）・全 fold Δ≥0・機序が単調係数の較正、の3点から、
grid 拡張は **in-sample 合わせ込みではなく汎化**。CV 採用根拠と整合し、done 可。

### caveat（CV レポート自身が明示する限界・転記）

`reports/cv-train-20260614-2254.md:90-92`: 「v021_core は F-005 エラー分析に使用済み。本 CV の
held-out は v021_core 内の分割であり、人手封印(F-013)ではない。汚染ゼロの最終 verdict ではなく、
『学習が CV で汎化するか』の分析」。→ 本監査の「汎化」判定は **CV held-out スコープ内**の判定であり、
F-013 封印評価による最終 verdict ではない（これは grid 拡張固有の弱点ではなく、t3.fit 全体の前提）。

## テスト緑で出ない穴（隠れ過適合・座標降下初期値の意図せぬ移動）

### ★穴1: 座標降下初期値 `_W_FLIP_GRID[2]` の意図せぬ移動（2.0 → 0.5）★

**所在**: `src/supreme/t3.py:732`
```python
best = {
    ...
    "w_flip_accum": _W_FLIP_GRID[2],
    ...
}
```
`fit()` の座標降下は `_W_FLIP_GRID[2]`（**インデックス参照**）を初期値に使う。

- 旧 grid `(0.5, 1.0, 2.0, 4.0, 6.0)`: `[2]` = **2.0**
- 新 grid `(0.0, 0.25, 0.5, 1.0, 2.0, 4.0, 6.0)`: `[2]` = **0.5**

→ grid 先頭に2要素を足したことで、座標降下の **w_flip_accum 初期値が 2.0 から 0.5 へ意図せず移動**
している。差分の表向きの意図（探索空間拡張）には初期値移動は含まれていないが、インデックス参照の
副作用として発生する。

**影響評価**:
- 座標降下は局所最適手法であり、**初期値が最終 params に影響しうる**（大域最適は保証されない）。
  したがって CV held-out 0.4429→0.5333 という採用根拠は「grid 候補 0.0/0.25 が選べること」と
  「初期値 2.0→0.5」の**両方の合成効果**であり、純粋な探索空間拡張の効果と分離されていない。
- 同様の初期値移動は `bias` grid 等では起きない（それらの grid は無変更）。w_flip_accum のみ。
- 決定性・param 数・後方互換（default_params）には影響しない（fit 内部の収束点の問題）。

**この穴がテスト緑で出ない理由**: `test_F009_fit.py` は fit の出力値を契約せず決定性のみ見るため、
初期値が動いて収束点が変わっても緑のまま（同データ2回 fit は依然同一）。CV レポートも「最終 acc」
しか見ず、初期値移動と探索空間拡張を切り分けていない。

**判定への影響**: 採用根拠（held-out 改善・gap=0）は CV 実測値であり、初期値移動を含んだ状態で
測られている。よって「この差分の現状での汎化」は崩れない（実測が汎化を示す）。ただし、もし設計意図が
「初期値は据え置いて探索空間だけ拡張」だったなら、`_W_FLIP_GRID[2]` を**値指定**（例: `_W_FLIP_GRID.index(2.0)`
相当や明示定数）にするのが意図に忠実。現状はインデックスのまま「たまたま 0.5 が初期値」になっており、
将来 grid をさらに編集すると初期値が再び無言で動くリスクが残る。
