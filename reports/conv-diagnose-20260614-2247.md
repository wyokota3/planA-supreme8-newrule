## 5b. t3 conv 境界較正プローブ — mode 列を core 現行で固定(上流無改変)

**上流 mode 列を core 現行のまま固定**し、t3 の conv/traffic ロジスティック重みだけを振って、
conv_participating の取りこぼしが **t3 較正だけで** どこまで説明・回復できるかを測る(in-sample・
楽観値=この絶対値は正直な汎化ではない。傾向の切り分けが目的)。default が現行 t3 既定 params。

| t3 params | t3 全体 acc | conv recall | conv 取りこぼし先 |
|---|---:|---:|---|
| default | 0.3905 | 5 / 29 | {'quiet_stable': 5, 'traffic_unstable': 16, 'uncertain_context': 1, 'env_shift': 2} |
| w_flip_accum=1.0 | 0.4429 | 14 / 29 | {'quiet_stable': 11, 'traffic_unstable': 1, 'uncertain_context': 1, 'env_shift': 2} |
| w_flip_accum=0.0 | 0.5048 | 15 / 29 | {'quiet_stable': 11, 'uncertain_context': 1, 'env_shift': 2} |
| bias_conv=-1.0 | 0.4143 | 10 / 29 | {'quiet_stable': 5, 'traffic_unstable': 11, 'uncertain_context': 1, 'env_shift': 2} |
| w_flip=1.0,bias_conv=-1.0 | 0.4571 | 18 / 29 | {'quiet_stable': 8, 'uncertain_context': 1, 'env_shift': 2} |
| w_flip=1.0,w_conv=10,bias_conv=-1.0 | 0.4667 | 21 / 29 | {'quiet_stable': 5, 'uncertain_context': 1, 'env_shift': 2} |

> 既定 classify_t3: conv_score = w_conv_ratio·conv_ratio + bias_conv、
> traffic_score = w_switch_rate·switch_rate + **w_flip_accum·flip_accum** + bias_traffic。
> GT=conv_participating フレームでは上流 conv_ongoing が持続し conv_ratio は上がるが、単一の
> mode 切替(flip_accum=1)が w_flip_accum=4.0 で traffic_score を底上げし conv を負かす。
> w_flip_accum を下げると conv→traffic の取りこぼしが解消する(mode を一切変えずに)。

## 6. 判定 — (A) 構造バグ / (B) 較正 / (C) genuine

観測サマリ:
- GT=conv_participating: 29 フレーム
- うち入力に会話証拠が在る: 29(100%)
- うち supreme が conv 系 mode を emit: 72%
- うち supreme t3 が conv_participating を正答: 5
- conv_request 結線で mode acc Δ=-0.0190・偽陽性 4 / 改善 0
- conv_request(speaking_link)結線で t3 conv_participating recall Δ=+1
- **mode を一切変えず** t3 較正のみ(w_flip_accum 低減): conv recall 5→21 / 29、t3 acc 0.3905→0.4667(in-sample 楽観)

### 観測からの切り分け(観測値のみ・捏造なし)

1. **会話証拠は入力に在り、上流 mode へ届いている(genuine = (C) は主因でない)**: GT=conv_participating 29 フレームは **全件** speech track + speaking link を持ち(present 100%)、うち 72% は上流が conv_ongoing を emit している。会話証拠が無い genuine フレームではない。

2. **取りこぼしの主因は (B) t3 conv 境界の較正**: 上流が conv_ongoing を出していても t3 が traffic_unstable へ流す(16 件)。原因は classify_t3 の **w_flip_accum=4.0** が、単一 mode 切替(flip_accum=1)だけで traffic_score を 底上げし conv を負かすこと。**mode を一切変えず** w_flip_accum を下げるだけで conv→traffic の 取りこぼしが解消する(5b 表)。これは学習境界の較正であって mode 結線の構造バグではない。

3. **副次的に (A) mode 側の弱会話取りこぼし**: speaking_prob ≤ 0.7 で conv_strong(strict `>`)に届かないが speaking link + speech + 近接があるフレーム(ns002/ns004/ns006/ns009 の先頭)は、**core が抽出済みの speaking_link を _mode_logits が使っていない死配線**のため quiet_standby/forward_caution に潰れる。ただし speaking_link は crowd/surround/quiet 区間にも現れるため、広く結線すると mode 偽陽性 4 件・acc Δ=-0.0190(前回の過適合判断は**広い結線では成立する**)。humans<3 ∧ speaking≥0.5 へ narrow すると偽陽性は 2 件に減り mode acc は微増(diagnose 標準出力の narrow 試験)だが**偽陽性ゼロにはならない**。

**結論**: 残る t3 conv 取りこぼしの **主因は (B) t3 conv 境界較正(w_flip_accum 過大)**で、**上流 mode を変えずに**最大の回復が得られる(クリーン)。conv_request 未結線(=(A) 構造)は 副次要因で、この v021_core には conv_request 専用証拠(addressing/call_user)が存在せず、speaking_link 流用は偽陽性ゼロにできない(前回の過適合判断は妥当)。
