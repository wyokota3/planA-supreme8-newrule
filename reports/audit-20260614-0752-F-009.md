### 観点2 / F-009-2: リセット初期化（核心・最重点）

**実現箇所**: `src/supreme/t3.py:438-446`（`step` の reset 分岐）、`:118-131`（`initial_state`）、`:134-163`（`_advance`）

reset 分岐の両側を確認:
- **True 側（初期化）**: `step`（`t3.py:439-440`）は「フレームを処理する**前**に」`state = initial_state()` を実行。`initial_state`（`t3.py:118-131`）は全カウンタ 0・`prev_mode=None`・`window=()` の決定的初期値。これにより「`reset=True` で frame X」＝「`initial_state` から frame X を1回流した状態」が厳密等価（実装コメント `t3.py:438`・ADR 0020 決定3 B と一致）。
- **False 側（継続）**: reset が偽かつ `state` が非 None のときは初期化せず `_advance(state, mode)` で前状態へ累積を継続（`t3.py:443`）。

```python
# t3.py:438-440（reset=True は処理前に初期化＝過去エピソードの蓄積が消える）
    # reset=True(またはエピソード境界)は処理前に状態を初期化する。
    if reset or state is None:
        state = initial_state()
```

**無限累積しないこと**: 集約累積（`conv_count`/`switch_count`/`flip_count`/`frame_count`）は reset で 0 に戻る。posterior 窓は reset 非依存でも `_advance`（`t3.py:152-154`）で `_WINDOW=64`（`t3.py:80`）に丸められ常に有界。「reset を挟むと累積が減る」ことは `flip_count` で観測可能。

**テストでの固定**:
- `test_F009_reset.py:65-95`（reset 後の hypothesis 列＝初期状態からのエピソード先頭と一致・厳密等価）
- `:98-125`（reset が持続conv累積を消す）
- `:133-174`（`episode_features` の `.conv_ratio`/`.switch_rate`/`.flip_accum` が reset 後に初期値復帰・`==` で厳密等価）
- `:177-207`（**無限累積しない**: reset を挟むと `flip_accum` が `< reset無し` になる）
- `:214-232`（**False 側**: reset=False で持続conv比率が単調に保たれ/育つ＝分岐の対）
- `:235-254`（境界: 初期状態への reset=True は reset=False と等価＝消す過去が無い）
- `:261-284`（系列 API でも reset 後部分がエピソード先頭列と一致）

これにより reset 分岐の True/False 両側・系列 API・境界（先頭 reset）が網羅されている。

**判定**: **実装済**。注入 reset 後に状態が初期値へ戻り（hypothesis・集約特徴の両面で厳密等価）、reset を挟むと累積が減り、無限累積しない。reset 分岐の両側が正しい。F-009 の最重点条件は満たされている。

### 観点3: エピソード集約特徴（機構の正しさ・有界性）

**実現箇所**: `src/supreme/t3.py:170-270`（`_Features` / `_trend` / `episode_features`）

機構の符号構造をコードで確認:
- **conv_ratio**（持続conv比率, `t3.py:249`）= `conv_count / frame_count`。conv 系判定は `_is_conv_mode`（`t3.py:87-89`・`startswith("conv")`）で、conv 系だったフレーム割合 [0,1]。**単一スパイクで飛びつかない**: 非conv 7 + conv 1 では `1/8=0.125`（持続を要求）。持続 conv なら 1.0 に漸近。
- **switch_rate**（`t3.py:250`）= `switch_count / frame_count`、**flip_accum**（`t3.py:251`）= `flip_count`。flip は `state.prev_mode is not None and label != state.prev_mode`（`t3.py:144`）で初手を切替に数えない＝過剰計上しない。持続（同一 mode）では 0、頻繁切替で上昇。
- **posterior_mean/var**（`t3.py:258-260`）= 窓の標本平均・標本分散（分散は二乗和/n で非負保証）。
- **posterior_trend**（`t3.py:201-221`）= 等間隔 x の最小二乗回帰の傾き。要素数 < 2 は 0.0（平坦扱い）。上昇で正・下降で負・平坦で 0（`t3.py:215-221` の `num/den`）。

**有界性**: posterior 窓は `_WINDOW=64` で丸める（`t3.py:152-154`）。集約特徴は窓または累積カウンタから O(1)/O(W) で算出され、エピソード長に対し有界（窓 ≤ W）。

**テストでの固定**: `test_F009_aggregate.py:114-141`（[0,1]・非負・分散非負）、`:148-190`（持続conv→1.0 / 単一スパイク< 0.5 / 持続 > まばら＝ns016/ns007 分離根拠）、`:198-241`（頻繁切替→switch_rate/flip_accum 上昇・安定→≈0）、`:249-290`（posterior 平均が入力反映・トレンド符号が上昇正/下降負/平坦≈0）。

**判定**: **合格**。集約特徴は機構として正しく（単一スパイクで飛びつかない・持続で上昇・トレンドが向きを符号で捉える）、窓 ≤ W で有界。ADR 0020 決定1 の集約特徴セット（持続conv比率 / 切替率 / flip累積 / posterior 平均・分散・トレンド）が全て実装されている。

### 観点8: 学習モジュールの落とし穴（過適合・符号の構造的保証）

集約・分類の符号が**構造的に**保証されるかを確認:
- `classify_t3`（`t3.py:367-384`）の3スコアは線形:
  - `conv_score = w_conv·conv_ratio + bias_conv`
  - `traffic_score = w_switch·switch_rate + w_flip·flip_accum + bias_traffic`
  - `quiet_score = bias_quiet`
- argmax の tie-break は `conv > traffic > quiet` の固定順（`t3.py:376-383`）で決定的。
- `default_params`（`t3.py:391-413`）の重みは全て正（`w_conv_ratio=6.0` 等）・バイアス負（境界用）。よって「持続conv比率↑→conv」「切替率/flip累積↑→traffic」「どちらも低→quiet」は**特定入力でなく重みの符号と特徴の単調性から構造的に成立**する。特定シナリオでのみ成立する過適合ではない。
- **飛びつき是正の構造的根拠**: 分類器の入力は瞬間 posterior でなく「持続conv比率」（`t3.py:356`）。低 conv_ratio + 高 posterior_mean では conv に勝てない（posterior は conv_score に入らない）。これは閾値ではなく入力特徴の選択による構造的保証（`test_F009_classify.py:228-241` が固定）。

**残存する設計上の注記（リスクではない・申し送り範囲）**:
- `traffic_score` は `posterior_trend`/`posterior_var`/`posterior_mean` を**使わない**（学習可能重みは conv_ratio/switch_rate/flip_accum の3特徴のみ）。posterior 集約3特徴（mean/var/trend）は `episode_features` で算出・公開されるが、`classify_t3` の3スコアには現状寄与しない。ADR 0020 決定1 は「トレンド等で ns016群の分離を試みる」とするが、**ns016群分離の成否は F-013 の成功目標・残件**（ADR 0020 残件「なお分離不可なら残差として記録」）であり、step1 では「トレンド特徴が存在し符号を捉える」機構の固定までがスコープ（`test_F009_aggregate.py:263-290`）。したがって本件は**スコープ内で正**であり、trend を分類に配線するか否かは F-013 の学習実験で決まる申し送り事項。仕様/ADR と矛盾しない。

**判定**: **合格**。集約・分類の符号は重みの符号と特徴の単調性から構造的に保証され、特定入力でしか成立しない過適合ではない。posterior 集約特徴の分類器配線は ADR 0020 残件（F-013 委任）として正しくスコープ外に置かれている。
