### 観点1: HGF カーネルの性質充足

#### 1-a. 決定性(乱数・時刻なし)
**実現箇所**: `src/supreme/scene.py:99-164`(`hgf_filter`)
- `import` は `math` のみ(`scene.py:35`)。乱数(`random`)・時刻(`time`/`datetime`)の import・呼び出しは無い(`scene.py` 全文走査で該当なし)。

**判定**: 実装済(構造的に決定的)。
**コメント**: テスト `test_F010_hgf_filter_is_deterministic_identical_trajectory`(`tests/test_F010_hgf.py:68-82`)が μ1 列・volatility 列の**完全一致**(ε=0 相当の `==`)を固定。

#### 1-b. 水準追従(層1 μ1 が観測水準へ追従)
**実現箇所**: `src/supreme/scene.py:137-144`
```python
v1 = math.exp(ka1 * mu2 + om1)
pi1_pred = 1.0 / (1.0 / pi1 + v1)        # 拡散後の予測 precision。
muhat1 = mu1
e = u - muhat1                            # 層1 prediction error
pi1 = pi1_pred + obs_pi                   # posterior precision
mu1 = muhat1 + (obs_pi / pi1) * e         # posterior 平均(観測へ寄る)
```
**判定**: 実装済。
**コメント**: `mu1` は precision 加重で観測 `u` 方向へ更新される標準的 Gaussian filter 更新。一定入力では gap が縮む(`test_F010_hgf_mu1_tracks_constant_level`・`tests/test_F010_hgf.py:116-131`、`..._moves_toward_level_monotone_enough`・同 134-150)。

#### 1-c. ボラティリティ応答(核心・見逃し是正)
**実現箇所**: `src/supreme/scene.py:147-162`
```python
rate2 = 1.0 / (1.0 + math.exp(-(mu3 + om3)))   # sigmoid -> (0,1)
target = math.log(e * e + _LOG_FLOOR) + om2
mu2 = mu2 + ka2 * rate2 * (target - mu2)
...
vol_out.append(math.exp(mu2))             # ボラティリティ(常に正)
```
**判定**: 実装済(3性質すべて構造的に成立)。
**コメント(構造的成立の定性検証・観点7と連動)**:
- **持続変化 vol > 定常 vol**: 層2 は `log(e^2)` を漏れ追従する。持続的に逸脱し続ける列では `e` が一貫して非ゼロ → `target` が高位で安定 → `mu2`(=log-vol)が高位へ寄る。定常列では `mu1` 収束後 `e≈0` → `target≈log(1e-12)+om2≈-29.6`(強い負)→ `mu2` が引き下げられ低ボラ。**特定入力列に依存しない一般機構**で成立(`tests/test_F010_hgf.py:166-182`)。
- **持続変化 > 1ステップ跳ね(見逃し是正の核心)**: 単発跳ねは跳んだ1ステップだけ `e` が大きく、以後 `e≈0` で `target` が低位へ戻り `mu2` が**減衰**する。持続変化は末尾まで `e` 非ゼロを保つため `mu2` が高位を維持。よって末尾 vol で sustained > single-step(`tests/test_F010_hgf.py:201-223`)。**「平坦に張り付くと drift→0 で見逃す」baseline 欠陥(ADR 0019 計測)への構造的対処**であり、漏れ追従の性質から導かれる(列値に過適合していない)。
- **非負**: `volatility = exp(mu2)`(`scene.py:162`)は実数 `mu2` に対し常に正。`_LOG_FLOOR=1e-12`(`scene.py:52`)で `e=0` でも `log` のドメインエラーを回避(決定的)。`mu3` は `[-4,4]` にクランプ(`scene.py:156-159`)し `rate2∈(0,1)` を有界化(発散防止)。テスト `test_F010_hgf_volatility_is_nonnegative`(`tests/test_F010_hgf.py:97-109`)が定常・変化両列で固定。

**性質充足の総合判定**: 既定 params(`default_hgf_params`・`scene.py:71-96`)で4性質(決定性・水準追従・ボラ応答・非負)が成立する**設計**になっている。ボラ応答は `log(e^2)` 漏れ追従という汎用機構から導かれ、テスト入力列の特定値に依存しない(観点7参照)。

### 観点7: 学習モジュールの落とし穴(過適合の定性評価)

**論点**: 「性質テストを通すために既定 params をテストに合わせ込んだ結果、ボラ応答が**特定入力列でしか成立しない過適合**になっていないか」。

**判定**: 過適合の兆候なし(構造的に保証されている)。
**根拠(定性)**:
- ボラ応答は層2 が `target = log(e^2) + om2`(`scene.py:150`)を**漏れ追従**する機構から導かれる。これは「持続的に PE が非ゼロなら mu2 高位・PE が 0 に戻れば mu2 低下」という**入力列の具体値に非依存な単調機構**。テストの特定列(`0.5+0.02*i` 等)は機構の**代表例**にすぎず、任意の持続変化列で `e` 非ゼロが続けば同じ向きに作用する。
- 既定 params(κ2=0.1=slow walk・ω2=-2.0・`scene.py:84-89`)は応答の**スケール**を決めるが、大小関係(changing>stationary, sustained>single-step)の**符号**は機構が保証する(params をテストに合わせ込んだのではなく、漏れ追従の構造が符号を決める)。
- `_LOG_FLOOR=1e-12`(`scene.py:52`)で `e=0` の定常列が `target` を強い負へ押す → 定常側が確実に低ボラになる(過敏抑制の機構的保証)。
- 持続性特徴も同型: 漏れ積分 `acc <- clip(acc + gain*dev - leak*acc, 0, cap)`(`scene.py:254-258`)は「逸脱が続くほど漸近値 `gain*dev/leak` へ近づき、単発は leak で減衰」という**汎用機構**。テスト(`tests/test_F010_persistence.py:150-181`)は機構の帰結を確認しており、特定列への過適合ではない。
- **残る正当な限界(申し送り・リスク低)**: 性質テストは「大小の**向き**」のみ固定し、`vol_high`/`persist_high` の**絶対スケール**と実 scene 列での分離性能は固定しない。これは ADR 0019 のスコープどおり(実 acc 改善は F-013 の成功目標)で**正**だが、「既定閾値グリッド(`scene.py:370-372`)が実データのボラ/持続スケールに整合するか」は F-013 の fit/測定で初めて検証される。step1 構造確定としては妥当。

## リスク評価

**リスク: 低**

根拠:
1. 性質(決定性・水準追従・ボラ応答・非負)が**特定入力列でなく汎用機構**(log(e^2) 漏れ追従・漏れ積分)から導かれ、過適合の兆候がない(観点7)。
2. 予算(U24)・独立性(決定4)が機械チェックで固定され、`guard` 再利用・非改修を確認。過学習防止の構造が崩れていない。
3. fit の非決定経路(乱数/時刻/dict反復/集合/浮動小数累積順)を逐一否定済み。
4. 未充足は **F-013 の成功目標**(実 acc 改善)と**スコープ外**(診断抽出)に限られ、いずれも ADR 0019 で「正」と確定済み。
5. 残る軽微な申し送り2点(下記)はいずれも F-003/F-012/F-013 の後段で扱える性質で、F-010 の step8 進行を妨げない。

## 推奨アクション

- **done 判定: 可**。F-010 を WORKFLOW step8(status.json 更新・ダッシュボード再生成)へ進めてよい。F-010-1 は「F-013 で測定する成功目標」として明示的に残すこと。
- **申し送り1(優先度: 低)**: `_LEARNABLE_PARAM_NAMES` は HGF 6個を学習対象として宣言するが、現 `fit` は閾値3個のみ tune し HGF param は既定固定。これは安全側(予算は最大宣言値で検査)で矛盾ではないが、F-013/F-012 で「HGF param も学習対象に広げる」場合は予算計上が既に 9 を含むため追加計上不要であることを記録しておくこと(食い破り防止の整合確認)。
- **申し送り2(優先度: 低)**: `fit` の `zip(feats, gt)`(`scene.py:417`)・`classify_sequence` は signal/gt の長さ不一致や空列・NaN/Inf を明示検証しない(U15 横断エラー方針 未確定のため現状は正)。F-003/F-012 で練習データ品質が固まる際、学習入力の前提(長さ一致・有限値)をデータ規律側で保証するか、本モジュールで明示エラー化するかを決めること。
- **推奨3(優先度: 低)**: step8 で `specs/ARCHITECTURE.md` の `scene` ノード緑化と、HGF 共有基盤の将来再利用(quality/anomaly)の図示有無を確認(図とコードの整合維持)。本監査では明確なズレ未検出。
