## 結論(author 合成多様化は t3/scene の held-out に効くか)

実のみ(n=0)を基準に、author 合成 14 件投入での held-out 改善 Δ:

| 層 | 実のみ(n=0) | 実+author(n=14) | 最終Δ | 効くか(効果曲線で判定) |
|---|---:|---:|---:|---|
| t3_hypothesis | 0.4095 | 0.4095 | +0.0000 | **no(全 n 同値・平坦)** |
| scene_regime | 0.5571 | 0.5571 | +0.0000 | **no(全 n 同値・平坦)** |

> 「効くか」は **n=max の単発比較でなく効果曲線全体**で判定する(非単調=合成多様化でなく
> 決定的 tie-break の揺れ・単調増=多様化が効く・全 n 同値=平坦)。

> held-out 採点分母: t3_hypothesis=210 / scene_regime=210 フレーム
> 検証は **実 held-out のみ**(合成は train だけ・検証に混ぜない=リーク禁止)。
> 合成 GT が悪ければ実 held-out の改善が出ない設計(=合成 GT の悪さは自動検出される)。

### なぜこの結果か(機構診断)

- author 投入(0→14 件)で **t3 学習 params が変化した fold = 1/5**、**scene 学習 params が変化した fold = 0/5**。
- 合成が決定的 fit を動かさない(params 不変)なら held-out は変わりようがない(=合成は学習に効かない の直接証拠)。
- **重要な構造的事実**: 本生成器が厚くした t3 クラス(sustained_alert / crowd_tendency /
  alert_required / env_shift)は t3 の **規則層**(`t3._rule_hypothesis`=baseline `_classify_t3`
  の忠実再現)が mode 窓比率から決める **固定規則** であり、**学習対象(conv/traffic/quiet
  境界のロジスティック重み)ではない**。よって、これらのクラスを構成的に厚くしても、
  学習可能 param(t3=6個=conv/traffic/quiet 境界)を動かす材料にはならない(規則層は学習で変わらない)。

## author シナリオの構成(どのクラスをどう構成的に作ったか)

構成定義 14 件 → 構成妥当性自己検査 OK で採用 **14** 件 / 破棄 **0** 件。

**GT 構成の根拠(各層・意味論)**:
- t2_mode = 作者が固定した intent mode(R チャネル証拠を core._mode_logits の発火条件へ
  排他的に当てて一意化:siren ttc≤2→emergency / 2<ttc≤12→alert_required / speech∧speaking>0.7∧range<5→conv_ongoing / humans≥3→surround_activity / 低 QoS→env_change)。
- t3_hypothesis = mode 系列(6 フレーム窓)へ baseline `_classify_t3` 意味論
  (`t3._rule_hypothesis` の規則 + `classify_t3` の conv/traffic/quiet 境界・default_params)を
  **構成的に適用**(run_supreme 非経由=円環回避)。
- risk_tier/t1_state/t2_role/t2_relation/quality_regime = 各 per-frame 証拠の決定論的判定規則
  (t0/t1/role/relation/quality の文書化済み意味論)から構成。
- scene_regime = 構成的に一意な **定常端点のみ**(全フレーム高 QoS→STABLE / 全フレーム低 QoS→
  DEGRADING)。混在(過渡)は HGF 系列依存で一意でないため **GT を付けない(None=学習サンプル外)**。

## 構成妥当性の自己検査(意図した mode-sequence/evidence が実際に出る入力か)

各 author シナリオを **core.run_supreme(snaps) に流し、得た各層が構成的 GT と一致するか** を
確認した。これは「意図した evidence/mode-sequence がその入力から一意に実現するか」の
**健全性チェック**であって、GT のラベル付けではない(GT は意味論で構成済み)。一致しない
(構成が一意でない)シナリオは **採用しない=捨てて報告**(無効ラベルで水増ししない)。

- 採用(自己検査で全層 intent 一致)= **14** / 破棄(構成不一致)= **0**

(全 14 構成定義が自己検査 OK。env の立ち上がり(env_start)・env を中途に挟む遷移は
HGF 遅延で構成的に一意化できないため **そもそも構成定義に含めない**=作る前に除外した。)

> **構成上の honest finding(HGF 遅延)**: env_change は h_q<0.5 で立つが、h_q は観測 logit を
> HGF で平滑化した量のため、高 QoS の **後** に低 QoS を置いても h_q が即座に 0.5 を割らない
> (2 フレームの過渡)。よって「quiet→env の立ち上がり(env_start)」は構成的に一意に作れない
> (過渡で mode 系列が intent と食い違う)。**全フレーム env_change の定常列だけ**が構成的に
> 一意(env_shift)。env_start を合成で厚くできないのは合成の原理的限界の一例である。

## caveat(厳密性に関する注記)

1. **合成 GT は穴5(合成)・円環回避**: author の GT は baseline 規則 / GT_SCHEMA の
   **文書化済み意味論**で構成的に決めたラベルであり、**supreme.run_supreme でラベル付け
   していない**(自己ラベル=円環は禁止)。GT は学習信号のみ・verdict / 封印には使わない。
2. **検証は実 held-out のみ**: author 合成は train だけに入れ、検証(採点)には一切入れない
   (リーク禁止)。合成 ID は独立 root(実 v021_core と非交差)。合成 GT が悪ければ実 held-out の
   改善が出ない=合成 GT の悪さは自動検出される。
3. **構成的に一意な範囲のみ**: GT が一意に定まらない状況(env の過渡・HGF 系列依存の scene
   遷移)は **作らない / GT を付けない**(無効ラベルで水増ししない)。env_start を合成で厚く
   できないのは合成の原理的限界。
4. **規則層と学習層の区別(最重要)**: 厚くした t3 クラスの多くは t3 規則層(固定・学習対象外)の
   出力。学習可能 param(conv/traffic/quiet 境界)を動かすには、その 3 境界が誤る多様な状況が
   要る。合成でそこを的確に作れているか自体が本実験の問い。
5. **in-sample 性**: v021_core は F-005 エラー分析に使用済み。本 CV は v021_core 内の分割であり
   人手封印(F-013)ではない。汚染ゼロの最終 verdict ではなく「合成多様化が CV で効くか」の分析。
