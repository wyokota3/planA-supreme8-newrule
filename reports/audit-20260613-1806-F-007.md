### M4: tie-break — 減衰後に遷移先==quiet（差ちょうど block）は quiet_standby を選ぶ

**実現箇所**: `src/supreme/mode.py:69-77`
```python
    best_label = None
    best_value = None
    for label, value in effective.items():
        if best_value is None or value > best_value:
            best_label = label
            best_value = value
        elif value == best_value and label == QUIET:
            best_label = label
    return best_label
```
**判定**: 実装済
**コメント**: ADR 0015 決定2 の式「block 減算後に他mode が quiet 以下なら quiet」（`decisions/0015-f007-mode-hysteresis.md:38` 系・ADR 残件記載と整合）を、`value > best_value`（厳密 `>`）＋ `value == best_value and label == QUIET`（同値なら QUIET を上書き）で符号化。差ちょうど block では `env_change=2.6-2.6=0.0 == quiet 0.0` となり、QUIET 側が選ばれる。テストで境界の両側を固定:
- 差==block ちょうど（env_change 2.6）→ quiet_standby（`tests/test_F007_mode_hysteresis.py:130-137`）
- 差が block を僅かに超える（env_change 2.7 → 0.1>0.0）→ env_change（`:140-146`）

`>=` であれば差==block で遷移先が勝ち仕様違反になるが、実装は厳密 `>` ＋ QUIET 優先 elif で正しい。

### M5（M4 の重点）: tie-break は辞書反復順序に依存しない（quiet が常に勝つ）

**実現箇所**: 同上 `src/supreme/mode.py:69-77`
**判定**: 実装済（順序非依存）
**コメント**: 観点1 の重点。QUIET と非QUIET が同値で最大タイになる2通りの反復順を解析した:
- **QUIET が後**: 先に非QUIET が `best`（値 v）になる。続く QUIET は `value(=v) > best_value(=v)` が偽、`value==best_value and label==QUIET` が真 → `best_label` を QUIET に上書き。**QUIET が勝つ**。
- **QUIET が先**: QUIET が `best`（値 v）になる。続く非QUIET は `value(=v) > best_value(=v)` が偽、elif も `label==QUIET` が偽で不発 → `best_label` は QUIET のまま。**QUIET が勝つ**。

いずれの反復順でも QUIET が勝つため、**M4 の tie-break は dict 反復順序に依存しない**。これは「quiet が常に勝つか」の重点確認に対し肯定。テスト `:130-137`（差==block の tie で quiet）が実挙動を固定。さらに `:154-165`（複数の弱い遷移先 env_change 2.0 / conv_ongoing 1.5 / surround_activity 1.0 が全て減衰→ quiet）/ `:168-179`（弱い遷移先に1つ強い conv_ongoing 3.5 が交じれば conv_ongoing へ）で、複数遷移先下でも QUIET 優先と強い証拠の通過が両立することを固定。

**残る微細点（QUIET が絡まない非QUIET 同士のタイ）**: 非QUIET ラベル2件が減衰後に同値で最大になる場合（例 prev=quiet で env_change と conv_ongoing が共に block 超過かつ同値）、`>` の厳密性により**先に現れた方**が `best` となり、後者は上書きされない＝**dict 反復順序に先着優先で依存**する。ただし (a) ADR 0015 決定2 の tie-break 規定は「他mode が quiet 以下なら quiet」＝QUIET 境界のみを対象とし、非QUIET 同士のタイ解決を規定していない（スコープ外の自由度）、(b) Python 3.7+ の dict は挿入順が決定的で、同一入力に同一出力を返すため**決定性（F-004-1 流儀）は破れない**（後述「決定性」）、(c) F-007 の入力 logit は上流（スコープ外）が生成する連続値で、厳密同値の非QUIET タイは実運用上ほぼ生じない。よって仕様違反ではないが、**ADR が非QUIET タイの解決順を明文化していない既知の自由度**として記録する（推奨アクション参照）。

## 決定性（観点2）

**判定**: 適合（決定的な純関数）

- 乱数: `random` / `numpy` / `torch` のインポート・呼び出しなし（`src/supreme/mode.py` のインポートは `from __future__ import annotations` のみ・`:27`。grep 検証済み）。
- 時刻: `time` / `datetime` の参照なし（grep 検証済み）。
- 状態: モジュールレベルの可変状態・グローバル副作用なし。`hysteresis(logits, prev_mode)` は引数のみに依存。前フレーム argmax のみ参照する局所機構で、エピソード状態を持たない（ADR 0015 決定2 `:41` の T3 非干渉に適合）。
- dict 反復順序: Python 3.7+ で dict は挿入順を保つ決定的反復。同一 `logits`（同一キー順）に対し同一出力を返す。QUIET 関与のタイは M5 のとおり順序非依存。非QUIET 同士のタイのみ先着優先だが、同一入力なら同一順序＝同一出力で**結果は揺れない**（乱数・時刻による揺れは皆無）。
- テスト: 決定性は `tests/test_F007_mode_hysteresis.py:234-264` が代表7点（過剰遷移抑制・強い証拠・安全 mode 即発火・差==block tie・prev≠quiet・複数遷移先）で「2回呼び出し同一」を明示固定。

## スコープ遵守（観点3・ADR 0015 決定1・3）

**判定**: 適合

- **証拠→logit 生成（段1-2）を実装していない**: `hysteresis(logits, prev_mode)` は logits を**引数で受け取る**のみ（`src/supreme/mode.py:44`）。PSO 入力からの特徴抽出・ルール logit 加点（`new_entity→env_change+2.0` 等）のコードは存在しない。docstring（`:3-6`）が「証拠抽出→ルール logit の生成（baseline t2.py の段1-2 相当）・温度 softmax・EMA は上流の共有基盤であり、本モジュールでは扱わない（ADR 0015 決定1）」と明記し、コードもそのとおり。ADR 0015 決定1（`decisions/0015-f007-mode-hysteresis.md:29-33`）に適合。
- **softmax / EMA を実装していない**: 指数化・温度・移動平均のコードなし（`:58-77` は減算・比較のみ）。事後分布も扱わず、入力 logit と前フレーム argmax から v1.4 mode ラベル1個を返すのみ。
- **境界群（side_rear/siren）の是正に手を出していない**: `forward_caution↔side_rear_caution`（旧 alert_observation・9件）/ `forward_caution→emergency`（siren・7件）を救済する角度ゲート緩和・siren 感度変更等のコードは存在しない。siren→emergency は M2 の安全即発火で**意図的に吸収しない**（安全リスク回避）。ADR 0015 決定3（`:45-49`）の「ラベル意味論/安全方針の別課題＝スコープ外・申し送り」に適合。

## オーバー実装の検出（観点4）

**判定**: なし（仕様にない実装は検出されなかった）

- **学習なし**: モデル・パラメータ学習・データ読み込みのコードなし。ADR 0013（`decisions/0013-u1-improvement-allocation.md:36`）の「ルール改良項目（mode/relation/quality）は学習しない（param 予算を消費しない）」、ADR 0015 残件（`:66`）「学習はしない」に適合。
- **prev≠quiet での独自ヒステリシスなし**: M3 のとおり `else: effective = logits`（素の argmax）のみ。ADR が規定しない「quiet 以外起点のヒステリシス」を勝手に足していない。
- **契約外機能なし**: 公開シンボルは `hysteresis` と定数 `BLOCK` / `QUIET` / `SAFETY_MODES` のみ。ロギング・設定・I/O・キャッシュ・確認カウンタ等の付随機能なし。ADR 0015 残件（`:62-64`）が「確認カウンタ等の最小状態は T3 と責務が触れるため本 ADR では持ち込まない」と明記しており、状態を持たない実装はこれに適合（カスケード限界は既知として申し送り）。
- **入力範囲外処理の追加なし**: logits のキー検証・v1.4 語彙の閉性検査・NaN 特別扱い等は実装されていない。出力は `logits` のキーのいずれかを返すのみ（語彙の正しさは上流が保証する分担）。これはオーバー実装の回避として妥当。
- **stdlib のみ**: サードパーティ依存ゼロ（インポートは `from __future__ import annotations` のみ・`:27`）。
- **他モジュール非改修**: `mode.py` は datagov/sealset/augment/guard/harness/quality/erroran を import しない（grep 検証済み・`:23-24` の言及は docstring の非改修宣言のみ）。`src/supreme/__init__.py:6-15` への mode 登録は ADR 0006 で予定済みの公開構成（10〜11行目・`__all__` に `"mode"`）であり改修にあたらず、他モジュールの実体には触れていない。

## 計測根拠との整合（観点6）

実装機構（M1〜M5）に ADR 0015 の代表ケースを適用し、計測根拠（`decisions/0015-f007-mode-hysteresis.md:42`「是正13・副作用8・純増+5・acc 0.6238→0.648」）の機構と突合した結果、**代表3類型すべて整合**。

| 類型（ADR 0015 計測） | 入力(logits, prev) | 実装機構の評価 | 期待 mode | テスト |
|---|---|---|---|---|
| 差<block 抑制（過剰遷移是正・new_entity→env_change 10件系） | ({quiet:0.0, env_change:2.0}, quiet) | M1: 2.0-2.6=-0.6<0.0 → quiet | quiet_standby | `:48-54` |

特に「差<block 抑制」と「安全 mode 即発火」の対（M1 vs M2）が、ADR 0015 の「過剰遷移を抑えつつ安全 mode は遅延させない＝是正13・副作用8（全て真の遷移 onset の1フレーム遅延）」というトレードオフ（`:42-43`）を境界で正しく符号化していることを確認した。block=2.6 が baseline/planA 計測値であり supreme 独立実装後の logit 分布で最終確認（F-013・ADR `:66`）という前提も、定数 `BLOCK=2.6`（`:35`）として faithfully に保持されている。

- tie-break 境界（M4）: 差==block（env_change 2.6）→ quiet（`:130-137`）/ 差 block 超（env_change 2.7）→ env_change（`:140-146`）
- 複数遷移先（M1/M5）: 全弱 → quiet（`:154-165`）/ 1つ強で遷移（`:168-179`）
- v1.4 語彙の閉性: 代表5点が10クラス集合内（`:200-227`）
- 決定性: 代表7点で2回呼び出し同一（`:234-264`）

### テストされていない振る舞い
1. **非QUIET 同士の最大タイ（M5 の残る微細点）**: prev=quiet で 2つの非安全遷移先が共に block 超過かつ減衰後に厳密同値で最大になる場合の解決順（先着優先＝dict 反復順序依存）を固定するテストがない。ただし ADR 0015 決定2 の tie-break 規定は QUIET 境界のみで、非QUIET タイの解決順は未規定（スコープ外の自由度）。決定性自体は破れない（同一入力＝同一順序＝同一出力）。done を阻害しない。
2. **安全 mode 同士のタイ（emergency と alert_required が同値最大）**: 両者とも減衰されず、先着優先でどちらが勝つかのテストがない。ADR は安全 mode 集合内の優先順位を規定していない（両者とも「安全側に発火」する点は満たす）。スコープ外・実運用稀。
2 と 1 は同じ「非QUIET タイの順序自由度」の系。
3. **prev_mode が logits のキーに存在しないケース**: prev=quiet 以外で、その prev ラベルが logits に含まれない場合（例 prev="forward_caution" だが logits に forward_caution キーなし）。M3 の素 argmax で logits 内の最大が返るだけで破綻しないが、専用テストはない。上流が「前フレーム argmax は当該フレームの logit キー集合に含まれる」を保証する分担なら問題ないが、その不変条件は ADR/SPEC に明文がない（後述・推奨）。
4. **logits が空 dict のケース**: 空なら argmax ループが回らず `best_label=None` を返す。実運用で空 logit は上流が出さない（10クラスを常に出す）想定だが、契約に明文・テストなし。スコープ外。

いずれも ADR 0015 のスコープ・決定2 の規定範囲内で、done を阻害する欠落ではない。1〜2 は ADR が非QUIET タイ順を規定していないことに由来する自由度であり、仕様違反ではない。
